## 1. Verdict

**APPROVE_WITH_NITS**

The revised artifact reproduces exactly (blob `0348384f`, SHA256 `9885f424…`, 83163 bytes, single added file, base is ancestor, clean tree, embedded text = committed bytes), and — decisively — the two blocking determinations from the rejected round are **closed on their merits, not by narrative**, and every load-bearing schema/source binding the new design depends on **exists exactly as written**:

- **W admission is now window-scoped, not purchase-scoped** (closes GLM R1 HIGH#1 / DeepSeek R1 F1). Admission authority is a new immutable `workspace_refund_test_authorities` row (order_id PK, unique PI/charge/payment/transaction, `window_id` UNIQUE→one order per window) produced by a private `bind-purchase` mutation under a real `LOCK TABLE orders IN SHARE MODE NOWAIT` transaction. This is exactly the "separate exact persisted authority, never actor-only" contract of the accepted money spec §8.
- **DELETE is removed from the entire lifecycle** (closes GLM R1 HIGH#2 / DeepSeek R1 F3). No DELETE/PATCH/upsert on the fixture secret, ever; deactivation terminates at `inactive_with_retained_custody`. The final-GET→external-write→name-DELETE race is structurally eliminated — there is no destructive operation left to lose a race.

The concurrency model that supports the registration is **technically correct PostgreSQL** (SHARE↔ROW EXCLUSIVE conflict, NOWAIT fast-fail, `pg_advisory_xact_lock` release-on-rollback), and I independently confirmed the single most novel hazard it guards against — the `_safe_scalar`/`_safe_execute` rollback-and-continue behavior in `surgical_reset.py` — is real and characterized exactly. Findings are **one LOW** (the new suppression-seam disjunct is evaluated for every synthetic event and must be proven not to disturb the shared s1656/s1681 paths) and **two NITs**. The verdict agrees with the findings. **This approves the concrete design only** — it certifies no implementation (all new files verified absent), no test pass (six baseline product failures remain; I claim no product test passes), no live activation/deactivation, and no AWS/R2 release. ## 4. Answers to the six numbered questions

**Q1 — Can an old same-pair W order, another window/order, P/N, or an altered canonical purchase binding gain signed TEST refund admission?**
**No — window-scoped registration closes this.** Admission is not the purchase chain anymore; it is the immutable `workspace_refund_test_authorities` row: `order_id` PK, **UNIQUE** `transaction_id/payment_id/payment_intent_id/charge_id`, and `window_id` UNIQUE (one registered order per window). The predicate *locates the unique authority by provider IDs* and *independently compares all immutable authority/purchase/capture bindings and canonical hashes*; **"A fully available schema with no exact registration does not admit the order."** Baseline persists **before** purchase (Stage A opening receipt, `order_ids` sorted complete set under `orders SHARE`); the exact later registration (Stage B `bind-purchase`) recomputes the delta and requires **exactly one** new paid order with the full chain + fixed actors + full USD capture + immutable `immutable_scope_hash`/`review_hash`/`manifest_hash` — all verified to exist (§3). Post-close convergence is correct: a closed/recovery window "retains authority only for its originally registered charge/order and normal exact event/refund convergence; it cannot bind a second order." The signature/dedup seam (`webhooks.py:476-563`) and existing-money-only lock chain (event→order→transaction→money-state→Payment→Refund, no DML, no state creation — "Do not invoke `lock_order_money_sync` if it would INSERT a missing state; missing state refuses") are respected. **No invented fields** (§3). An old same-pair *unregistered* order, another window's order, P/N (seller01 + `authority_kind`), or an altered scope/publication/pin has no registration row and is refused. *Residual (L1):* the predicate must not disturb the shared s1656/s1681 disjuncts.

**Q2 — Can concurrent public purchase, duplicate binder, or backend surgical reset defeat complete baseline/cardinality/history preservation?**
**No, as designed — and the PostgreSQL semantics are correct.** Reset↔open serialization uses a fixed transaction-scoped `pg_try_advisory_xact_lock(1712,17002)` taken before any window/order lock or destructive SQL by both Stage A and the guarded reset. The **key insight is verified**: `surgical_reset.py:306-323` really does `db.rollback()`-and-continue on missing tables, which would release an xact-scoped advisory lock — so the spec correctly mandates a **strict path** (no swallowed rollback/reconnect/helper-commit) holding one transaction through `_reset_objects`/`_execute`. Cardinality preservation uses `LOCK TABLE orders IN SHARE MODE NOWAIT` before reads: SHARE conflicts with the ROW EXCLUSIVE that INSERT/UPDATE/DELETE acquire, so an **already-active** order writer makes binding fail-fast (`window_busy`), and a **later** writer blocks until commit — the table lock (not READ COMMITTED) is what excludes phantoms, which is the right tool. Bounds are explicit: `lock_timeout=250ms`, `statement_timeout=2000ms`, `idle_in_transaction=2000ms`, host 5s deadline; every window/order/money/Payment/Refund lock is NOWAIT; `55P03/40P01/57014`→rollback+whole-operation retry; **no order-lock upgrade**; duplicate binders serialize via `SELECT FOR UPDATE NOWAIT` on the window row + `window_id` UNIQUE. An extra order purchased after bind cannot gain authority and makes close/deactivate cardinality proof refuse (paid rows retained/reconciled, never deleted). The spec correctly requires **real two-session PG tests** ("measure the actual bounds rather than sleep and assume ordering") and states "This is not a claim that flock serializes public buyers." *Note:* the advisory guard is taken only by reset targets seller02/buyer01 — a seller01/buyer02-targeted reset is not serialized but is caught by the `capture_protected_state` re-comparison before final success (fail-safe refusal, no silent acceptance); acceptable for a TEST fixture, worth a test.

**Q3 — Can credential/provider activation or recovery overwrite another generation, reassign a Party, or duplicate a resource?**
**No — and no DELETE/PATCH/upsert exists to do so.** Custody is create-once; first creation requires authenticated 404 + no prior retained generation + durable pre-POST record (generation UUID, operation UUID, name, digest, marker); conflict/uncertain reconciles by exact GET scope/name/marker/digest/ID/version, never overwrites; timeout/403/empty ≠ absence; an unposted-but-lost generation is recorded `abandoned` before a new one. Reuse only when the ledger and current UUID/version/digest/marker/scope/name all agree and no prior op is unresolved; drift refuses and preserves lineage. Because nothing is ever deleted/patched/upserted, an unseen post-read writer's credential cannot be erased (this is the structural closure of the old race). Account creation: complete-pagination enumeration, zero→create-only-if-no-uncertain-prior, one→validated reuse, multiple→refuse; expired idempotency never authorizes a fresh account; TEST provenance bound to the approved test credential + authenticated retrieval (reject explicit `true`; Accounts v1 has no `livemode`); Custom type + distinctness from seller01/platform. Party safety: the spec forbids the `upsert` (which reassigns `party_id`) before proving no foreign Connect identity and locking the exact Party/`auth_user` binding — projection + owned-identity creation in one transaction; commit-but-receipt-loss resumes by inspecting expected state. Fixed package names (`E2E_SYNTHETIC_SELLER_02_TOTP` added to `account_pool.json`, verified absent today) and typed projection/restoration (Stripe fields as strings; `totp_verified_at` nonnull RFC3339; `backup_codes_hash=null`; `updated_at` unmapped and not fabricated) are exact.

**Q4 — Can an unauthenticated public caller, wrapper bypass, substituted host artifact, or wrong image/pin gain authority, or can secrets leak?**
**No, under the honestly-scoped trusted-private-operator boundary.** The design is explicit that the authenticated local operator with `docker exec`/custody authority *is* the trust boundary and that a compromised operator is out of scope — it does **not** claim the mounted owner/runtime artifacts are a signature or an independent Docker measurement. Authority requires *all* of: the `check-settlement --lock` + unchanged `--guard seed` path (both exit 1 **and** exit 2 refuse before first write; `workspace-fixture` is outside the guarded-name set so the child must call the guard), a separately owner-issued artifact, and pin/hash/label match. Pins are correctly split (closing GLM R1 MED#3): `backend_local_image_id` = running `container.Image` = `docker image inspect .Id` = `.runtime/image-digests.json`; `backend_source_label` = `Config.Labels[ai.market.s1656.backend-sha]`; a registry/OCI **index** digest is explicitly never a substitute; "Re-discover exactly one project/service container directly; no cached snapshot or Compose polling." Actual Docker identity is the host's separate verification (retained as evidence), and the receiver "cannot independently call Docker and must not claim that comparing two caller strings measures its image." stdin is one UTF-8 object ≤16384 (read 16385 to detect overflow), duplicate-key/trailing/unknown/wrong-type/unsupported-version rejected before fixture imports; the only env assignment is the nonsecret `PYTHONPATH=/app` (closing DeepSeek R1 F4); read-only `/s1656` mount + read-only `/s1712-workspace-authority` mount; append-only per-operation directories, no path traversal/symlink, guarded `O_NOFOLLOW|O_NONBLOCK` reads; a real child-boundary canary proves no secret in argv/env/output/audit/exception. Deployment pins are re-checked before every mutating invocation and mismatch refuses before any write. No public route invokes the receiver; `status` is read-only.

**Q5 — Are every lifecycle/recovery transition and implementation target concrete?**
**Yes.** Opening (Stage A: advisory lock→`orders SHARE`→baseline capture→`state=open` commit), binding (Stage B: provider facts before locks→fresh txn→SHARE→window+order rows→money chain→one registration + `open→bound` in one commit), closing (`→closing`, recheck under short SHARE, requires unchanged baseline+one-registered cardinality, full refund, cannot-settle, terminal receipt), and deactivation (owned-readiness restore, retain custody/account/history) are **distinct**, with a DB-enforced forward-only state machine (`open→bound/closing/recovery`, `bound→closing/recovery`, `closing→closed/recovery`, `recovery→closing`; revision+1; `closed` immutable; partial-unique index → one nonclosed window; immutable trigger rejecting DELETE and identity/opening/baseline mutation). Commit/receipt loss reconciles exact immutable rows/bytes (backend row is authority; host files re-read by `inspect`). `reset/up/seed` refuse any present W authority/audit/custody lineage — including closed/no-purchase — before secret/S3/provider/container side effects, and `order_id` FK RESTRICT is defense-in-depth; **no paid rows dropped, no "missing schema = safe."** The normal capture/refund/payout processor remains the **sole** financial writer (readiness verified via `refund_processing_service`/`order_money_service`; W "never manufactures capture" and "never seeds chart or financial authority"). Regressions against accepted F1 are respected (start from accepted env `43d67264`/backend `c3`, retain buyer02 + P/N, serialize `webhooks.py`). Targets are concrete and — verified — currently absent (design-only). Before/expected field types are exact (§3). *Residual (L1):* the shared-seam disjunct behavior.

**Q6 — Are runbook/support/upgrade and real-release obligations complete and honest?**
**Yes.** The owner-evidence categories are enumerated and typed (`original/corrected × online/offline/summary/wrapper`, `scheduled_success`, `launchd_provenance`, `installed_plists`, `stable_release`, `money_gate4_bq`, `protected_before`), each a `{category,identity,path,sha256}` with guarded reads, and — critically — the design is explicit that the **owner attestation is trusted operator evidence, not a fabricated independent verifier**: "host validation checks completeness of the declared categories, exact bytes/hashes and operation/reference binding, not a fictional independent proof of operator honesty," and "No bare success boolean is accepted." Current-vs-future identity is honest: run25 preserved on `03d3f30`/`d766` with genuine hold `2026-09-13T23:41:11…` and original+corrected P/N 48-hour holds ordered **before** a separate W namespace via explicit owner transition; "environment merge does not release the owner window"; stable release/money Gate4/BQ + production **quiescence/trigger-freeze** ("current main triggers all have checkSuites=false") named as separate execution gates; "a seed fixture, test account, health check or unanimous design review does not prove full AWS/R2 production release." Finite transport limits (the §17.3 VC/raw-HMAC gap, unmapped `BillingEntity.doppler_key_prefix`, the same-class wallet loader, and the six baseline failures) are disclosed and **not certified**. The Sept-12 historical paid-order observation is kept distinct from fresh availability/transport. **No future run IDs, missing completion, or authority extension are invented** — Mars's unanswered extension request is explicitly "not an approved extension." The diagnosis map, support-bundle allowlist (no bearer URLs/TOTP/raw provider bodies/DB URLs), and upgrade rules (refuse unknown audit versions without rewriting; never run an old payment binary over new authority) are concrete.

### SIMPLER
**None found that preserves the invariants; advisory.** The two-table split (`workspace_test_windows` lifecycle state machine + immutable `workspace_refund_test_authorities` per-order row) is the minimum that supports both "one nonclosed window" and "one immutable registered order per window" with a fully-immutable authority row and a controlled-transition window row — folding them would entangle the immutability trigger with the state machine. No scope violation supports a mandate.

**None materially better — the revision converged on the better approach.** The predecessor GLM/DeepSeek/CC "BETTER" was precisely a first-class backend-owned registration state machine with retained (never-deleted) custody; this revision **is** that design, and it correctly places the predicate in its own module (`app/services/workspace_refund_test_admission.py`) mirroring `s1681_refund_test_admission.py` rather than inline in the contended `webhooks.py`.
