Reviewer: **CC** (independent voter; author Vulcan S1712 is not a voter). Read-only; nothing modified, no test/lock/provider/DB/credential/runtime action taken. All shell via `rtk`. Budget: ~10 of 30 turns used; two parallel read-only Explore agents corroborated the backend and environment claims.

## 1. Verdict

**APPROVE_WITH_NITS**

The artifact identity is exact, the accepted dependencies are correctly bound, and — decisively — the two flagged **blocking design questions resolve in the design's favor on independently verified evidence**, not on the builder's narrative:

- **W exact-window authority (Q1):** purchase-scope is **adequate**; a persisted per-window W registration table is **NOT required**. The W predicate uses *existing* schema (`delivery_authorities` / `cloud_connections`), rejects every dangerous class (P/N, foreign seller, real/livemode, agent/device, synthetic-lookalike), and its blast radius is strictly TEST-synthetic. Mars needed a registration row only because P/N are amount-identical siblings — a disambiguation need W does not have.
- **Infisical custody (Q2):** the create-once / bind-ID-version-digest-marker / re-read-under-owner-lock / **preserve-on-any-drift** / authenticated-404 design **satisfies the authority invariant under the stated exclusive-custody precondition**, which is enforceable for a dedicated fixture secret; the uncloseable sub-operation TOCTOU is correctly handled by fail-safe preservation, and demanding a CAS endpoint is out of scope.

No HIGH or MEDIUM survives verification. Findings are two substantive LOW rulings (the answers to the two blocking questions, with conditions) plus two source-anchored NITs. The verdict agrees with the findings. **This approves the concrete design only.** It certifies no implementation, no test pass, no live activation/deactivation, and no AWS/R2 release; the forward "Gate2 must bind/test X" items are the design's own conditions and must be met before MP builds and before any owner activation window.

### L2 — LOW — Infisical exclusive custody satisfies the authority invariant only under an operational exclusivity precondition; the design is correct but must carry that precondition and the "cleanup incomplete" outcome explicitly. (My explicit Q2 ruling.)
- **repo@SHA / evidence.** `runbooks@e138f16a…:…GATE2.md:75,77,79` (DELETE has no version/UUID precondition → read-then-delete is not CAS; bind ID/version/digest/marker, re-read under owner-held shared fixture lock, require exclusive ownership, preserve on any drift, authenticated-404≠timeout/403/empty; create-once-never-upsert). Backend corroboration that the underlying secret is a real dedicated fixture: `E2E_SYNTHETIC_SELLER_02_TOTP` is referenced by-name-only in `ai-market-backend@c3a62af8…:e2e/account_pool.json` and `app/e2e/account_pool.py:24-34` (which actively forbids inline credential values).
- **Observed vs expected.** Observed: the maximum the published raw API allows — no server-side compare-and-delete — so a sub-operation TOCTOU (independent writer changes the secret between re-read and name-DELETE) is theoretically possible. Expected: never delete/overwrite another generation or party's credential. The design closes every path *except* the concurrent-authorized-writer TOCTOU, which it addresses by requiring exclusive custody (eliminating the concurrent writer) and by preserving on any observed drift.
- **Reproduction:** static evidence only.
- **Impact.** LOW. The invariant holds because on *any* observed drift the item is preserved; the only way to wrongly delete is the sub-ms TOCTOU under a concurrent authorized test-env writer, which exclusive custody forbids and which **no non-CAS design can close.** The request explicitly bars demanding a fictional CAS endpoint.
- **Smallest required outcome.** Gate2 must (i) make "owner-held shared fixture lock for the entire operation" a stated precondition, (ii) permit `custody_changed` cleanup to terminate as **"cleanup incomplete, secret preserved"** (nonzero, non-destructive) rather than force-delete, and (iii) test create-response-loss, authenticated 404-vs-403, external version change, mismatched metadata, and deleted/recreated-same-name-ID (the spec already enumerates these at `:79,144`).
- **Verification criterion.** The custody tests demonstrate preserve-on-drift and the "incomplete" terminal state; no path performs a name-only delete without matching ID+version+digest+marker.

## 4. Answers to the six numbered questions

**Q1 — Can the W webhook exception admit another order, P/N, arbitrary synthetic actor, or out-of-window refund? Immutable purchase-scope vs exact-single-window.**
**No dangerous admission; purchase-scope is the correct authority and a per-window registration table is NOT required.** The predicate + seam reject: non-W orders (`authority_kind` CHECK, `seller_workspace.py:665-670`); P/N (different seller + `authority_kind`; and P/N's own registration is Mars-owned); foreign/arbitrary actors (fixed seller02/buyer01 with publication listing/seller/version equality and matching connection owner); real/livemode (the seam only touches `_stripe_event_is_e2e_synthetic` events, `webhooks.py:563`); agent/device-backed transactions and synthetic lookalikes (explicit rejects, `:55`). Refunds survive credential/storage revocation because the immutable chain persists (`CloudConnection` retained on revoke; FK RESTRICT) and the predicate validates retained bindings, never active download eligibility (`:55,120`). The single *residual* — cross-window multiplicity of valid W orders — is a proof-orchestration property, not a money/authority one, and is discharged host-side (snapshot-delta refuses zero/multiple new paid orders; terminal-cleanup-before-next-window; W receipt binds one order; replay for same-ID). The webhook is right to refuse to trust the host receipt as DB authority. **Blocking test:** none of P/N/foreign/real/agent/device is admissible, and the host helper refuses ≠1 new paid W order — see L1. Missing exact authority? No — the immutable purchase chain is real and sufficient. Undisclosed schema extension? No — existing schema only, and any registration is explicitly deferred as a reviewable extension.

**Q2 — Can credential/account activation or cleanup overwrite/delete another generation or party?**
**No, given the design's exclusive-custody precondition and fail-safe preservation.** Custody: create-once-never-upsert, bind ID/version/value-digest/marker, re-read under owner lock, **preserve on any drift**, authenticated-404 required for absence (`:75,77,79,142`); interrupted-before-POST records abandoned generation and mints a new discriminator (`:77`). Account: enumerate the complete marked result set (zero→create only if no uncertain prior; one→validated reuse; multiple→refuse), expired/interrupted idempotency never authorizes a fresh account, TEST provenance bound to the approved credential + authenticated retrieval with explicit-`true` rejected (Accounts v1 has no `livemode`), Custom type + distinctness from seller01/platform verified (`:91,93,156,158`). Party binding: **`upsert_stripe_connect_identity` genuinely reassigns `party_id` on conflict (`stripe_connect_identity.py:124-133`)** — so the spec's rule "validate/lock the exact Party/auth_user binding and prove no foreign Connect identity *before* projection; never call the upsert first" (`:95`) is load-bearing and correct; projection + owned-identity creation in one transaction; DB-commit-but-receipt-loss resumes by inspecting expected state, never enrolls a new secret or moves an account (`:95,160`). User field types are strings, not booleans, and the spec rejects the wrong scalar (`user.py:85-87` confirms). **Concrete required outcomes:** hold the fixture lock for the whole op; permit "cleanup incomplete / secret preserved"; test the external-writer race per L2. The external-writer TOCTOU is not waved away — it is bounded by exclusivity + preserve-on-drift, the maximum a non-CAS API permits.

**Q3 — Can a wrapper bypass the settlement lock/guard, mutate before refusal, leak a secret, or silently repair audit?**
**No, as designed.** Mutation enters the absolute-command `check-settlement --lock` (path-validated parent = `ROOT/bin`) then the unchanged `--guard seed`; because `workspace-fixture` is outside the guarded-name set (confirmed), the child *must* call the guard, and **both exit 1 and exit 2 are treated as pre-write refusal** (`:43,108`). `status` is read-only and writes no token/audit (`:43`); default `bin/seed`/`bin/reset` must refuse an active/inconsistent audit and gained readiness *before* S3 cleanup/container destruction — "placing the check only in seed.py is too late" (`:108,173`, and reset/seed guard-early is confirmed). Private stdin ≤16384 (read 16385 to detect overflow), duplicate-key/trailing/non-object/unknown/wrong-type/unsupported-version rejected before fixture-writing imports (`:47`); no secret in argv/env/Compose/tempfile; tokens live only in host process memory; a **canary test drives the real child boundary** and proves absence from argv/outputs/audit/exceptions (`:45,51,116,120`). Errors return a stable category with no provider body/input fragment/traceback; raw responses never logged (`:49,79`). Audit is fsync+atomic-rename, 0600, symlink/mismatched-ownership rejected, persisted only under guard success, never rewritten to unblock (`:85`); local imageId vs OCI index distinctness and pin-mismatch-refuse-before-writes are required (`:65,135`). No fallback to live S1681 roots in tests (`:120`). Non-blocking; the exits/foreign-lock/stdin/canary tests must exist.

**Q4 — Can crash/retry/deactivation lose a paid role or duplicate resources?**
**No, as designed.** Every provider/credential/DB/audit boundary is bracketed by durable pre-records and inspect-after-commit recovery (`:91,95,97,160,162`). Provider account: complete-pagination enumeration; multiple-match refusal; expired/interrupted idempotency never mints a new account; uncertainty retained. Credential: uncertain create reconciled against the same operation + digest; never overwrite; timeout ≠ absence. Connect identity: projection guarded by the ownership proof that defeats the real upsert-reassignment risk (Q2). Deactivation restores only enumerated captured fields, removes only the exact newly owned Connect row, **never deletes Party/auth_user** (`:104,169`), and refuses destructive cleanup while any payout/refund/aggregate is uncertain or any new W order lacks a terminal, cannot-settle refund/release state (`:103,168`) — i.e., explicit terminal W financial disposition precedes destructive cleanup. TEST provider accounts with financial history are retained with recorded disposition (`:106,171`). Non-blocking; crash-injection before/after each durable step and provider-stub pagination/duplicate/uncertain cases are required (`:122,187`).

**Q5 — Does the frozen scope implement the whole accepted Gate1 without copying over F1 or changing normal money behavior?**
**Yes.** Frozen targets (`:112`) are a minimal, coherent set: env (`bin/workspace-fixture` new, `seed/workspace-host.py` new, `seed/seed.py`, `bin/reset`, `bin/seed`, tests, `workspace/README.md`) + backend (`e2e/account_pool.json`, `webhooks.py` narrow W predicate only, tests), with **no new hook framework, no processor change, no N-table extension.** Mars owns the overlapping F1 env edits and the repin; Workspace starts from the accepted environment candidate (not old `c6b` copied over), retains buyer02 as protected, updates fixture cardinality from F1, and preserves P/N (`:114`). Load-bearing targets confirmed present: mounted receiver `/s1656/seed.py` (compose RO mount), the fixed nested operation schema (`:63-69`), the synthetic W predicate seam (`webhooks.py:563`), the packaged account configuration (IDs + name-only secrets), expected fixture cardinality (four accounts), and the readiness/`ensure_order_capture` cross-repo interface (exact but for N1). W reuses the dynamic merchant via readiness and the normal processor — it never seeds chart/financial authority (`:19,31,96`). No load-bearing target is missing; the only cross-repo mismatches are the two NITs. Suggested refactor (BETTER) remains advisory.

**Q6 — Are support, upgrade, and live-acceptance obligations concrete and correctly separated?**
**Yes.** Design vs runtime is explicit and repeated: "not a claim that these commands exist or have passed" (`:3`); pins deferred until the protected lifecycle permits (`:23`); "a seed fixture, test account, health check or unanimous design review does not prove full AWS/R2 production release" (`:157`). Run25 is preserved on `03d3f30`/`d766` with its genuine hold (`2026-09-13T23:41:11.491739Z`), ordered P/N before W, and an explicit owner transition before the separate W namespace (`:155`). Production trigger freeze/quiescence/reconciliation/migration are named as separate execution gates (`:37,153,157`); the §17.3 VC/raw-HMAC transport gap and the unmapped `BillingEntity.doppler_key_prefix` inherited defect and the six baseline failures are disclosed and *not* certified (`:9,11,15,25`). The support bundle excludes secrets/raw responses/bearer URLs (`:147`); upgrade qualification is independent of retry, refuses unknown audit versions, and is tested on an isolated copy (`:149,159`). The historical MP235 paragraph is explicitly labeled superseded (`:169`). Design approval here certifies none of the unexecuted implementation or the wallet/VC/raw-HMAC limits.

### SIMPLER
**None found that preserves the invariants.** The design is already at floor: it reuses the existing suppression seam (no new admission framework), introduces **no new table** (the anti-simplification the spec correctly avoided — see L1), reuses Mars's `canonical_digest` and lock order, and delegates all financial effects to the accepted processor. Things I tried to remove and rejected: (a) the W persisted-chain predicate — needed for W/N separation and revoked-authority refund; (b) a W registration table — correctly *not* added (would add scope without safety benefit for W); (c) collapsing `seed/workspace-host.py` into `bin/workspace-fixture` — already dispositioned advisory-and-rejected at Gate1 because the receiver must run *inside* the container against the read-only `/s1656` mount while the host holds custody and drives `docker exec -i`; one host entrypoint cannot do both. Advisory only; no scope violation supports a mandate.

### BETTER
**One materially cleaner structure, advisory.** Place the W predicate in its own backend module (e.g. `app/services/workspace_refund_test_admission.py`) imported and called at the seam, **mirroring how Mars structured `admits_s1681_negative_refund`/`admits_s1681_failed_run_refund`** in `s1681_refund_test_admission.py` (called from `webhooks.py:559-561`), rather than inline in `webhooks.py`. This directly reduces churn in the contended, serialized `webhooks.py` money-path file the spec itself flags (`:37,114`), and makes the W predicate independently unit-testable. Failure modes: negligible (pure read-only predicate); cost: one new backend file requiring a one-line allowlist addition (a much smaller extension than a table); rollback: trivial (docs/allowlist only). Weigh against the spec's stated preference to keep the change inline-and-narrow — hence **advisory, not a mandate** (no material risk). The Gate1 "generic hook framework" BETTER remains correctly declined; the existing disjunction point already *is* the narrow shared seam.
