## 1. Gate 1 product decision

“My own licence” is text the seller types or pastes into the listing form. There is no file picker, PDF or other file upload, malware scan, scanner service, or attachment. The text is the seller's own legal instrument and remains separate from the ai.market AI-Training Rider and Marketplace Listing Covenant. The training toggle defaults to yes; the seller must still confirm the covenant and authority. The buyer still gets the amber notice: the custom terms were not written by ai.market, ai.market is not a party, and the buyer should obtain their own legal review before accepting. Seller edits after a completed text submission invalidate the document id, hashes and approval until the changed text is checked and saved again.

The current [listing licences runbook](../runbooks/listing-licenses.md) describes the deployed upload implementation and failure codes. Update that operational page when code changes ship, including removal of `LICENSE_TEXT_NOT_NFC` from the new route's error inventory; this amendment does not claim the deployed route has changed.

## 3. Gate 2 API and validation contract

`POST /api/v1/licenses/custom` becomes a seller-authenticated, rate-limited `application/json` request: `{"title":"...","ai_training":true,"text":"..."}`. `title` is required, 1–255 characters after trim; `text` is a required JSON string; `ai_training` is an actual JSON boolean and defaults to `true` only when omitted. HTTP 201 returns `id`, the stored `title`, `text` (the canonical text, including its final LF), `content_type:"text/plain"`, `size_bytes`, `source_sha256`, `license_sha256`, and `status:"active"`. The added `text` key is required in the response model and strict frontend response validator; its UTF-8 bytes must hash to `source_sha256`. The seller preview uses this server-returned text, never the unsaved textarea value, before covenant/authority confirmation. Rename implementation functions/types from “upload” to “submit text” where practical, while retaining the route for listing selection compatibility.

Set **65,536 Unicode code points** as the maximum after canonicalization. A text area this long accommodates substantial legal terms while bounding database, record and browser rendering; even four-byte UTF-8 code points fit below the existing 1 MiB `license_documents.size_bytes` check. Count code points server-side (`len` in Python) and code points, not UTF-16 units, in the browser counter. Reject empty/whitespace-only canonical text and over-limit text as `LICENSE_SIZE_INVALID`; keep a 1 MiB raw request-body ceiling as defense in depth.

At the route boundary, run seller authentication and the existing fail-closed rate limiter before reading or parsing the body; then enforce the 1 MiB limit while streaming/buffering, before JSON parsing. Accept only media type `application/json` (case-insensitive, with optional `charset=utf-8` and no other charset); missing or other content types, including multipart, return HTTP 415 `{"detail":{"code":"LICENSE_DOCUMENT_INVALID"}}`. Read bytes with strict UTF-8 decoding; invalid UTF-8 returns HTTP 422 `LICENSE_TEXT_INVALID_UTF8`. Parse JSON strictly with duplicate-key detection, including keys equal after NFC normalization; reject malformed JSON, duplicate keys, non-object roots, unknown or missing fields, wrong field types (including numbers/null/strings for `ai_training`), or invalid title as HTTP 422 `LICENSE_DOCUMENT_INVALID`. No type coercion. The title is trimmed for storage and must contain 1–255 Unicode scalar values with no `Cc`, `Cf`, surrogates, noncharacters, or line separators. A route-local parser/exception handler must map FastAPI/Pydantic `RequestValidationError`, JSON decoding, and body-limit failures into this envelope rather than the framework's default validation array; body over limit returns HTTP 422 `LICENSE_SIZE_INVALID`. All content refusals below use HTTP 422 with `{"detail":{"code":code}}`; authentication and rate-limit responses retain their existing contracts. Do not log request text or title on refusal, and create no row on any refusal.

For **new custom text only**, define one authoritative form `C`: replace CRLF and lone CR with LF, normalize to NFC, remove trailing ASCII space and TAB from each line, remove all trailing LF characters, then append exactly one LF. This is the existing `canonicalize_document_text` result (`license_hashing.py:33-38`); do not add a second normalization in storage, download, acceptance, or clients. A leading U+FEFF is forbidden, so `C` has no BOM. Validate permitted characters before and after this transformation; then count `C`'s code points and encode `B = C.encode("utf-8")` with strict encoding. The persisted `full_text`, HTTP 201 `text`, listing/buyer text, frozen `license_acceptances.license_text`, and authenticated `.txt` response body are all exactly `C`/`B`, without subsequent trimming or re-canonicalization. `size_bytes = len(B)` and `source_sha256 = SHA256(B)`. `license_sha256 = hash_custom_text(C, {"ai_training": bool, "source_sha256": source_sha256})` retains the existing domain, length framing, canonical JSON and parameter semantics (`license_hashing.py:89-115,151-153`); its internal canonicalization is idempotent on `C`. The client must verify **both** `SHA256(received UTF-8 bytes) == source_sha256` and the recomputed component `license_sha256` over the same `C` and params before display/approval or purchase. Reject mismatches; never repair them silently. Existing uploaded-file text hashes and signed rows are never rewritten.

Published byte/hash vectors (hex is lowercase; these hash primitives need not pass the English-length hygiene rule):

| Input JSON text value | `C` | `B` hex | `size_bytes` | `source_sha256` | `license_sha256` with `ai_training=true` | with `ai_training=false` |
| --- | --- | --- | ---: | --- | --- | --- |
| `A  \r\nB` | `A\nB\n` | `410a420a` | 4 | `daee1cd25194ae952d046ad9b9c81d3c07dc5332440b58d6d7461b248be56712` | `089b5fc383a91cab83bcd343b4d84088ffa88bee1e0722b2aacb6f4e35488a88` | `a46e8d2b14a1a242b46fd0f90909c4bf8e890491944c4ff330b54da5481cb215` |
| `Cafe\u0301\rC\t\n\n` | `Café\nC\n` | `436166c3a90a430a` | 8 | `d46134a41760f4f038325c0b69df0cb47cd171208d26ecb6dd8c8871abea7515` | `01e47cbea636183300c55bf3a5ca48968b5dd164f71853c94867f8d673da8786` | `8103af7dfc67d05124e2bd28552035d8b34d4957b6acb0fca6d7603a9109892c` |

Reject any text containing Unicode category `Cc` except TAB, CR and LF in raw input (only TAB and LF after line-ending normalization), all category `Cf` including U+061C, U+200B–U+200F, U+202A–U+202E, U+2060–U+2069 and U+FEFF, all surrogate code points U+D800–U+DFFF (including escaped unpaired surrogates), all noncharacters U+FDD0–U+FDEF and plane-ending U+FFFE/U+FFFF on every plane through U+10FFFF, and U+2028/U+2029 line separators. Return `LICENSE_DOCUMENT_INVALID`; do not strip or neutralize forbidden characters. Other valid scalar characters may be accepted only if every seller/buyer/signed-record HTML view and generated record PDF can render them legibly. Use a Unicode-capable embedded PDF font and literal text layout preserving `C`'s LF/TAB meaning; preflight glyph coverage at submission and reject unsupported characters as `LICENSE_DOCUMENT_INVALID` before activation. The record PDF must preserve reading order and never silently substitute, drop or replace glyphs. HTML uses isolated literal text blocks and preserves whitespace; PDF and HTML checks must compare extracted/visible text to `C`, accounting only for layout wraps. This policy applies to new submissions; historical signed rows remain immutable.

A repeated identical seller/`C`/training submission may return the existing active document only when the submitted trimmed title matches its immutable stored title. A title-only change with the same seller/`C`/training returns 422 `LICENSE_DOCUMENT_INVALID` with no mutation or new row; the UI shows the stored title and requires the seller to revert the title for that document. The opposite training value gets a distinct licence hash and immutable row. The existing owner/hash uniqueness and selection recheck still apply. A changed text or training choice invalidates document id, hashes and approval; a title edit also invalidates approval until resubmission resolves to a valid row.

Keep `_require_english` (`custom_license_service.py:128-137`), `_reject_secrets` (`:84-95`) and `_reject_prohibited_terms` (`:40-50,140-145`) on `C`. The language check still requires at least 200 alphabetic characters and English confidence ≥0.90; a short document therefore returns `LICENSE_LANGUAGE_NOT_ENGLISH`, not a bypass. Preserve `LICENSE_SECRET_DETECTED` and `LICENSE_PROHIBITED_TERMS`. Surface these codes and the length/English requirement beside the seller text area without exposing rejected content in logs. The service raises `CustomLicenseError(code)` for content refusals; the endpoint rolls back and returns HTTP 422 `{"detail":{"code":code}}` (`licenses.py:53-55`). The complete new-route 422 code set is `LICENSE_SIZE_INVALID`, `LICENSE_DOCUMENT_INVALID`, `LICENSE_TEXT_INVALID_UTF8`, `LICENSE_LANGUAGE_NOT_ENGLISH`, `LICENSE_SECRET_DETECTED`, and `LICENSE_PROHIBITED_TERMS`. `LICENSE_TEXT_NOT_NFC` ceases to be emitted because valid decomposed text is normalized. Unexpected database failure returns HTTP 503 `LICENSE_UPLOAD_UNAVAILABLE` initially to preserve the existing external error contract; rename it only in a separately coordinated API change. No row is active on refusal.

Remove `scan_upload_for_malware`, `subprocess`/`clamscan`, `pypdf` parsing and PDF-active-content checks from **new submission** code (`custom_license_service.py:5-24,68-81,98-125,148-197`). Remove PDF/scan-only dependency references after checking their other repository uses. Do not install a scanner or add a scanner service. `LICENSE_MIME_MISMATCH`, `LICENSE_PDF_INVALID`, `LICENSE_PDF_ACTIVE_CONTENT`, `LICENSE_MALWARE_DETECTED` and `LICENSE_MALWARE_SCAN_UNAVAILABLE` cease to be emitted by the new route. Retain `LICENSE_TEXT_INVALID_UTF8` for malformed request bytes. Search Dockerfile/build context for ClamAV leftovers and remove only those that exist; `origin/main` has no `clamscan` or `clamav` reference in its Dockerfile, while `requirements.txt:78` still lists `pypdf` and `requirements.txt:4` lists `python-multipart`, whose other uses must be checked before removal. PR #464 is already closed unmerged; do not reopen or reuse it.

## 4. Storage, old PDF rows and rendering

It is simpler than an object-store read path and matches the current text branch (`license_document.py:17-25,35-43`; `custom_license_service.py:257-267`). Keep `malware_scan_status` **nullable** in a forward migration and drop its `='clean'` check. New rows write `NULL` and a hygiene report with language, secrets and prohibited-term results but no fabricated `malware:"clean"`. Existing `clean` values stay untouched for audit. This is an additive migration that preserves old rows and avoids a destructive column drop; align the ORM, migration tests and application writes. Do not modify the original S1735 migration or signed rows.

Before implementation deployment, an authorized operator runs this **read-only** production check through the established read-only database access path (the `S1738_READ_ONLY_DATABASE_URL` environment variable is supplied by that path; never paste its value into evidence):

```sh

BEGIN TRANSACTION READ ONLY;
SELECT content_type, status, count(*) AS documents
FROM license_documents
WHERE content_type = 'application/pdf'
GROUP BY content_type, status;
SELECT count(*) AS signed_pdf_acceptances
FROM license_acceptances
WHERE license_pdf_source_sha256 IS NOT NULL;
COMMIT;

```

Record timestamp, environment, aggregate counts and query identity, never legal text or object keys. If both counts are zero, remove PDF ingestion, PDF object writing and unused PDF serving code after the zero proof, but retain any immutable hash vector for historical verification. If either count is nonzero, **stop the text-only release until a reviewed compatibility plan is attached**: at minimum retain read-only authorized PDF retrieval, hash verification, existing signed-record PDF source references and object retention for those rows, while refusing new PDF submissions. Do not convert a PDF to text, change its hash, erase its object or silently make an existing signed licence unreadable. A separate migration/remediation decision is required before removal of that legacy read path. The production count is a release gate, not an instruction to mutate production.

Show `C` as escaped literal plain text in the seller preview, buyer listing and Buy screen, buyer/seller order history and signed-record HTML/PDF projections. Preserve line breaks and TAB spacing; do not execute HTML, Markdown, links, scripts or style from the seller's text. React text nodes and `<pre>` with directional isolation are appropriate; never use `dangerouslySetInnerHTML` with this text. The authenticated listing document endpoint returns `document["full_text"].encode("utf-8")` directly, without another call to `canonicalize_document_text`, as `text/plain; charset=utf-8`, with `X-Content-Type-Options: nosniff`, `Cache-Control: private, no-store`, the existing source/licence hash headers and an attachment `.txt` when `download=1` (`license_documents.py:54-97`). Both normal view and download must have bytes whose digest equals the source header. The public custom URL continues to show only the amber notice and hash. The signed-record renderer reads frozen `license_acceptances.license_text` (`license_record_service.py:126-153`) rather than current listing text, escapes it in HTML and passes it to the Unicode-capable record PDF renderer as literal text; the generated **record PDF** remains distinct from a seller-uploaded PDF. ## 7. Review decisions

1. **Recommended default:** 65,536 Unicode code points after canonicalization, with the 1 MiB raw body ceiling retained. Change only if a real seller licence exceeds this in a reviewed sample.
2. **Recommended default:** release only after the read-only PDF counts are zero; if nonzero, attach a specific compatibility plan before deployment rather than changing signed records.
3. **Recommended default:** hard JSON switch with only the custom submission route disabled during the bounded cutover; `LISTING_LICENSES_ENABLED=true` and its signed-record gate remain active throughout. Require an explicit compatibility window only if traffic evidence contradicts the low custom-submission premise.
