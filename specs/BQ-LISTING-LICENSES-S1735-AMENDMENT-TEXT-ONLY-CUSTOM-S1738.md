## 1. Gate 1 product decision

“My own licence” is text the seller types or pastes into the listing form. There is no file picker, PDF or other file upload, malware scan, scanner service, or attachment. The text is the seller's own legal instrument and remains separate from the ai.market AI-Training Rider and Marketplace Listing Covenant. The training toggle defaults to yes; the seller must still confirm the covenant and authority. The buyer still gets the amber notice: the custom terms were not written by ai.market, ai.market is not a party, and the buyer should obtain their own legal review before accepting. Seller edits after a completed text submission invalidate the document id, hashes and approval until the changed text is checked and saved again.

The current [listing licences runbook](../runbooks/listing-licenses.md) describes the deployed upload implementation, including current failure codes, at lines 20–32, 49, 58 and 231. Update that operational page when code changes ship; this amendment does not claim the deployed route has changed.

## 3. Gate 2 API and validation contract

`POST /api/v1/licenses/custom` becomes a seller-authenticated, rate-limited `application/json` request: `{"title":"...","ai_training":true,"text":"..."}`. `title` is required, 1–255 characters after trim; `text` is a required JSON string; `ai_training` is an actual JSON boolean and defaults to `true` only when omitted. Reject unknown properties and multipart/form-data. The success response remains HTTP 201 with `id`, `title`, `content_type:"text/plain"`, `size_bytes`, `source_sha256`, `license_sha256`, `status:"active"`; these are the existing response keys (`licenses.py:20-28`). Rename implementation functions/types from “upload” to “submit text” where practical, while retaining the route and response shape for listing selection compatibility.

Set **65,536 Unicode code points** as the maximum after normalization. A text area this long accommodates substantial legal terms while bounding database, record and browser rendering; even four-byte UTF-8 code points fit below the existing 1 MiB `license_documents.size_bytes` check. Count code points server-side (`len` in Python) and code points, not UTF-16 units, in the browser counter. Reject empty/whitespace-only text and over-limit text as `LICENSE_SIZE_INVALID`; keep a 1 MiB UTF-8 request/body ceiling as defense in depth. Reject malformed JSON, missing/incorrect fields, nonboolean `ai_training`, or extra keys as `LICENSE_DOCUMENT_INVALID` in the same 422 code envelope. Reject invalid UTF-8 JSON as `LICENSE_TEXT_INVALID_UTF8`. Reject raw NUL and other disallowed control characters (allow tab and line breaks) as `LICENSE_DOCUMENT_INVALID`. Enforce content type; a multipart request returns 415 `LICENSE_DOCUMENT_INVALID` and cannot create a row. Document this wire error separately from the content-validation 422 errors.

Normalize CRLF/CR to LF and Unicode to NFC **before** validation, character counting, UTF-8 encoding, storage and hashing. Do not silently trim meaningful licence text. Compute `source_sha256 = SHA256(normalized_text.encode("utf-8"))`; `size_bytes` is that byte length. The response and persisted `full_text` are the same normalized text. `hash_custom_text(full_text, {"ai_training": bool, "source_sha256": source_sha256})` keeps its existing domain, canonicalization and parameter semantics (`license_hashing.py:33-38,89-99,107-115,151-153`). Existing raw-file text hashes and signed rows are never rewritten. A repeated identical seller/text/training submission may return the existing active document; the opposite training value must get its distinct licence hash and immutable row. The existing owner/hash uniqueness and selection recheck still apply.

Keep `_require_english` (`custom_license_service.py:128-137`), `_reject_secrets` (`:84-95`) and `_reject_prohibited_terms` (`:40-50,140-145`) on the normalized UTF-8 text. The language check still requires at least 200 alphabetic characters and English confidence ≥0.90; a short document therefore returns `LICENSE_LANGUAGE_NOT_ENGLISH`, not a bypass. Preserve `LICENSE_SECRET_DETECTED` and `LICENSE_PROHIBITED_TERMS`. Surface these codes and the length/English requirement beside the seller text area without exposing rejected content in logs. The service raises `CustomLicenseError(code)` for content refusals; the endpoint rolls back and returns HTTP 422 `{"detail":{"code":code}}` (`licenses.py:53-55`). Unexpected database failure returns HTTP 503 `LICENSE_UPLOAD_UNAVAILABLE` initially to preserve the existing external error contract; rename it only in a separately coordinated API change. No row is active on refusal.

Remove `scan_upload_for_malware`, `subprocess`/`clamscan`, `pypdf` parsing and PDF-active-content checks from **new submission** code (`custom_license_service.py:5-24,68-81,98-125,148-197`). Remove PDF/scan-only dependency references after checking their other repository uses. Do not install a scanner or add a scanner service. `LICENSE_MIME_MISMATCH`, `LICENSE_PDF_INVALID`, `LICENSE_PDF_ACTIVE_CONTENT`, `LICENSE_MALWARE_DETECTED` and `LICENSE_MALWARE_SCAN_UNAVAILABLE` cease to be emitted by the new route. Retain `LICENSE_TEXT_INVALID_UTF8` for malformed request bytes. Search Dockerfile/build context for ClamAV leftovers and remove only those that exist; `origin/main` has no `clamscan` or `clamav` reference in its Dockerfile, while `requirements.txt:78` still lists `pypdf` and `requirements.txt:4` lists `python-multipart`, whose other uses must be checked before removal. PR #464 is already closed unmerged; do not reopen or reuse it.

## 4. Storage, old PDF rows and rendering

Use the existing `license_documents.full_text` DB column for new text; `content_type='text/plain'`, `object_key=NULL`, `size_bytes` and both hashes remain populated. It is simpler than an object-store read path and matches the current text branch (`license_document.py:17-25,35-43`; `custom_license_service.py:257-267`). Keep `malware_scan_status` **nullable** in a forward migration and drop its `='clean'` check. New rows write `NULL` and a hygiene report with language, secrets and prohibited-term results but no fabricated `malware:"clean"`. Existing `clean` values stay untouched for audit. This is an additive migration that preserves old rows and avoids a destructive column drop; align the ORM, migration tests and application writes. Do not modify the original S1735 migration or signed rows.

Before implementation deployment, an authorized operator runs this **read-only** production check through the established read-only database access path (the `S1738_READ_ONLY_DATABASE_URL` environment variable is supplied by that path; never paste its value into evidence):

```sh
rtk proxy psql -X -v ON_ERROR_STOP=1 --dbname "$S1738_READ_ONLY_DATABASE_URL" <<'SQL'
BEGIN TRANSACTION READ ONLY;
SELECT content_type, status, count(*) AS documents
FROM license_documents
WHERE content_type = 'application/pdf'
GROUP BY content_type, status;
SELECT count(*) AS signed_pdf_acceptances
FROM license_acceptances
WHERE license_pdf_source_sha256 IS NOT NULL;
COMMIT;
SQL
```

Record timestamp, environment, aggregate counts and query identity, never legal text or object keys. If both counts are zero, remove PDF ingestion, PDF object writing and unused PDF serving code after the zero proof, but retain any immutable hash vector for historical verification. If either count is nonzero, **stop the text-only release until a reviewed compatibility plan is attached**: at minimum retain read-only authorized PDF retrieval, hash verification, existing signed-record PDF source references and object retention for those rows, while refusing new PDF submissions. Do not convert a PDF to text, change its hash, erase its object or silently make an existing signed licence unreadable. A separate migration/remediation decision is required before removal of that legacy read path. The production count is a release gate, not an instruction to mutate production.

Show new custom text as escaped literal plain text in the seller preview, buyer listing and Buy screen, buyer/seller order history and signed-record HTML/PDF projections. Preserve line breaks; do not execute HTML, Markdown, links, scripts or style from the seller's text. React text nodes and `<pre>` are appropriate; never use `dangerouslySetInnerHTML` with this text. The authenticated listing document endpoint returns UTF-8 `text/plain; charset=utf-8`, `X-Content-Type-Options: nosniff`, `Cache-Control: private, no-store`, the existing source/licence hash headers and an attachment `.txt` when `download=1` (`license_documents.py:54-97`). The public custom URL continues to show only the amber notice and hash. The signed-record renderer reads frozen `license_acceptances.license_text` (`license_record_service.py:126-153`) rather than current listing text, escapes it in HTML and passes it to the PDF renderer as literal text; the generated **record PDF** remains valid and is distinct from a seller-uploaded PDF. Buyer and seller retain their role-specific identity projections.

## 7. Review decisions

1. **Recommended default:** 65,536 Unicode code points after LF/NFC normalization, with the existing 1 MiB byte ceiling retained. Change only if a real seller licence exceeds this in a reviewed sample.
2. **Recommended default:** release only after the read-only PDF counts are zero; if nonzero, attach a specific compatibility plan before deployment rather than changing signed records.
3. **Recommended default:** hard JSON switch with coordinated flag-off cutover, because the current scanner-bound multipart route is effectively unusable. Require an explicit compatibility window only if traffic evidence contradicts that premise.
