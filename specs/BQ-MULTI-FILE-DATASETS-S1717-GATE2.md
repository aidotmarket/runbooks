## 1. Scope and non-goals

In scope: the six chunks named by Gate 1 §6 (A–F), the one named by the amendment §6 (G), and one this document adds — C0, the shared sample infrastructure (§4.2a) — A (AIM Data model and upload), B (AIM Data processing), C (publish and sample, local route), D (delivery, local route — blocked, §4.4), E (verification over the set), F (copy and runbooks), G (workspace sample files). Every design rule is Gate 1's; this document cites it by decision letter.

Out of scope (Gate 1 §3, amendment §4): pricing/commission/payout, the S3 device route and S1681 G3.2, the Trust Channel protocol, merging or transforming member bytes, cross-dataset bundles, public per-member browsing beyond the sample, HF publication of sample files, R2 profiling (W3), any server-side object-body read of a seller's bucket.

All new production behaviour ships **fail-closed behind two flags**: `MULTI_FILE_DATASETS_ENABLED` exists in both repos — backend `app/core/config.py` and `aim-data:app/config.py` (AIM Data: a `multi_file_datasets_enabled: bool = False` field read through the existing alias helper `:45-47`, so the deployment name is `AIM_DATA_MULTI_FILE_DATASETS_ENABLED`) with default `false`, owned by chunk C0 (backend) and chunk A (AIM Data); `WORKSPACE_SAMPLE_FILES_ENABLED` is backend-only (C0): `MULTI_FILE_DATASETS_ENABLED` (AIM Data: directory registration, one-member registration of new uploads, local-route version publish, `member_files`; backend: `aim_data_local` publish acceptance, member endpoints, the **local branch** of the public sample endpoint) and `WORKSPACE_SAMPLE_FILES_ENABLED` (backend: chunk G upload/approval/reaper and the **workspace branch** of the public sample endpoint). **Flag matrix for the shared endpoint `GET /api/v1/public/listings/{listing_id}/sample/{index}`:** the resolver first determines the listing's route (`source_delivery.authority_kind`); a local-route listing serves only when `MULTI_FILE_DATASETS_ENABLED`, a workspace listing only when `WORKSPACE_SAMPLE_FILES_ENABLED`; any other combination is an indistinguishable 404. The two flags are independent, so the workspace route can go live before chunk D (§8). Builders test with the flags on.

## 3. Cross-repository contract and ownership

- **Manifest (D0), verbatim from Gate 1 D0:** an ordered list of members, each `{index, relative_path, size_bytes, sha256, detected_type, role, is_sample}` (`relative_path` canonical: NFC, forward slashes, no `.`/`..`, no leading slash; `detected_type` ∈ AIM Data's `PROCESSABLE_TYPES` ∪ `{unsupported}`; `role` ∈ `{data, documentation, other}`), plus scalars `member_count`, `data_member_count`, `sample_member_count`, `total_data_bytes`, `manifest_hash`. **Preimage:** `manifest_hash = SHA-256(canonicalize(members))` where `members` is the ordered list of the seven-field member objects **only** (the scalars are derived and never hashed) and `canonicalize` is the existing shared `python-json-sort-compact-v1` (sorted keys, no whitespace, UTF-8). `python-json-sort-compact-v1` canonicalization and SHA-256 are implemented **once in each repo** from one golden vector fixture (`tests/fixtures/multi_file_datasets/manifest_golden.json`, identical bytes in both repos, checked by a test that hashes it and compares to the fixture's recorded digest): AIM Data `app/services/dataset_manifest.py` (chunk A), backend `app/services/dataset_manifest.py` (chunk C0, with the fixture and the identical-hash test). The backend recomputes; it never trusts the sender's hash (AC3).
- **Publish wire (D3/D5):** `VZPublishPayload` gains top-level optional `agent_version: str | None`; `VersionPublish` gains `source_kind: Literal["s3","aim_data_local"] = "s3"` (Gate 1 D3's name; default so existing senders are byte-identical), and — **present only when `source_kind == "aim_data_local"`, refused otherwise** — `members_total: int` and `members_upload_id: UUID` (these two and the members endpoint are the carrier of Gate 1 D3's approved chunked member upload: they carry counts and an upload id, never member data, are default-gated, and sit outside Decision (0)'s wire enumeration because D3, not Decision (0), defines them); `listings.source_delivery.authority_kind = "aim_data_local"` is set by the receiver for directory publishes (D3); a new signed endpoint `POST /api/v1/vz/versions/{version_id}/members` accepts chunks of ≤ `PUBLISH_MEMBER_CHUNK` members carrying the full seven-field D0 tuple `{index, relative_path, size_bytes, sha256, detected_type, role, is_sample}`; activation when the receiver's recomputed manifest hash equals the declared one. The signed publish bytes for an S3/workspace publish without `agent_version` are unchanged (golden test, CC nit).
- **Store failure is fail-closed (C, G):** if the §9 store is unreachable, unauthenticated or refuses a write during a local-route publish, the version is **not activated** (it stays `pending_members` and is garbage-collected) and the publish is refused with `sample_store_unavailable`; the workspace upload endpoint refuses with the same reason and writes no row.
- **Sample assets (D4/G):** one store, one key layout: final `samples/local/<listing_version_id>/<index>/<sha256>` (chunk C) and `samples/workspace/<row_id>/<reservation_id>/<sha256>` (chunk G), staging `samples-staging/local/<listing_version_id>/<index>` and `samples-staging/workspace/<row_id>/<reservation_id>` (amendment W-D2), in the bucket of §9 D-G2-1; the two reconcilers never cross prefixes (amendment W-D3 (iii)).
- **Serving (D4/G):** one public endpoint family `GET /api/v1/public/listings/{listing_id}/sample/{index}`; the resolver branches on the listing's authority kind; headers, hash check, budgets and lifecycle per D4/W-D4.
- **Scan spec (E):** `listing_version_id` + `manifest_hash`, presence-discriminated, `spec_version "1"` (S1590 amendment §1.4).

## 9. Decisions for Max and known unknowns

- **D-G2-1 — the ai.market object store (money, infrastructure).** Recommendation: one Cloudflare R2 bucket `aimarket-listing-assets` in the existing Cloudflare account (the one that hosts the E2E buckets and the seller R2 route), with a dedicated API token scoped to that bucket, credentials in Infisical.
