Enforce `charge_total_cents=price_cents+buyer_fee_cents`, `0<=commission_cents<=price_cents`, USD, and unique order. A separate frozen quote row is inserted in the same transaction as each new paid card order. Backfill **all** existing card orders with `policy=platform_absorbs`, `B=0`, existing `P/C`, legacy version/terms marker; preserve their original payout behavior, including the three Gate 1 named orders. No date inference. The selection flag only affects newly created orders; rollback affects only later selection.

Add settings `SELLER_SALE_CARD_FEE_BEARER` (`seller` initially; enum `seller|buyer|split`), `SELLER_SALE_CARD_FEE_BUYER_SHARE_BPS` (0 initially, 0..10000, read only for split), and `SELLER_SALE_CARD_FEE_PASS_THROUGH_ENABLED` (false). **PROPOSED for panel review — ceiling `card-usd-v1`:** `r_max=1000 bps`, `f_max=50¢`, `minimum_transfer=1¢`; enable USD card seller sales on the US Stripe platform for Stripe-supported card issuing jurisdictions, with no buyer surcharge anywhere. [Stripe's US pricing](https://stripe.com/pricing) lists domestic 2.9%+30¢, international +1.5%, currency conversion +1%, and manually entered +0.5%: at most 5.9%+30¢ from those published components. The proposed 10%+50¢ is an engineering buffer, **not** Stripe's contractual cap; customized fees or other components can exceed it. Freeze the version and values on each order, and refuse payout/raise an exception if actual fee exceeds the bound. `P>=2500` per `MINIMUM_TRANSACTION_USD=25.0` (`app/core/config.py:696-699`). At `P=2500`, `C=125`, `A_max=ceil(0.10×2500+50)=300`, seller mode `T_min=2075`; floor passes. At `P=2499`, reject regardless of calculated margin. Card and geography eligibility, including international/FX tests, require panel validation; buyer/split stays disabled.

For an approved buyer share `b=buyer_share_bps/10000`, calculate `B=ceil[b(r_max P+f_max)/(1-b r_max)]` using integer rational arithmetic, one final upward rounding; seller mode uses `B=0`. Define `A_max=ceil(r_max(P+B)+f_max)`, `S_max=A_max` for seller, `0` for buyer, or `ceil(A_max×(10000-buyer_share_bps)/10000)` for split; `G_max=max(0,A_max-S_max-B)`. Refuse quote unless `P-C>=S_max+G_max+minimum_transfer`. Revalidate frozen `P+B` at payment/capture, and show `P`, separate `B` (zero or omitted for seller mode), and total before consent. Do not recompute commission on gross. Any `A>A_max` is an exception, not a substitute estimate.

## B. Actual-fee snapshot and payout/refund state machine

**Additive migration:** Add to `order_money_states`: `fee_snapshot_state` (`pending|frozen|exception|legacy`), `stripe_balance_transaction_id` unique nullable, `actual_fee_cents`, `seller_policy_share_cents`, `seller_gap_cents`, `seller_recovery_cents`, `buyer_fee_cents`, `buyer_excess_refund_cents`, `base_transfer_cents`, `seller_receivable_offset_cents` (default 0), `fee_frozen_at`, `fee_snapshot_sha256`, `no_transfer_reason`, and `recovery_journal_entry_id` nullable. Extend `payout_state` CHECK with `no_transfer`; require a reason and no transfer ID for that terminal state. Add nonnegative/check identities and a unique `(order_id,stripe_balance_transaction_id)` binding. Existing rows use `legacy` with null actual-fee fields. `seller_payout_posted_cents` remains **only** actual Stripe Transfer, not recovery or offset (`app/models/order_money_state.py:25-39`). Introduce `seller_receivable_accounts` (seller_id PK, open_cents nonnegative, updated_at), `seller_receivable_entries` (UUID PK, seller_id, order_id, kind/source_type/source_id, incurred_cents, recovered_cents, currency, journal_entry_id, timestamps; UNIQUE kind/source_type/source_id and CHECK recovered<=incurred), and `seller_receivable_offsets` (UUID PK, payout_order_id, entry_id, amount_cents, journal_entry_id; UNIQUE payout_order_id,entry_id). Use a dedicated seller-receivable asset GL account, code **1210**, in the chart.

After capture and before reservation, retrieve the platform `Charge` by captured charge ID and expand or retrieve its `balance_transaction` in platform scope using the normal Stripe client, **without** a connected-account header. Validate PI, charge, order, captured `amount=P+B`, USD, livemode, balance-transaction amount/net/fee/currency and no conflicting provider refund (`app/services/refund_processing_service.py:333-360`). The current optional PI expansion is insufficient (`app/services/finance/payment_service.py:171-184`). Provider I/O happens before DB locks; recheck immutable IDs and refund admission under locks. Freeze exactly once: `A=balance_transaction.fee`; `S=A` seller, `0` buyer, or `ceil(A×seller_share_bps/10000)` split; `G=max(0,A-S-B)`; `R=S+G`; `E=max(0,B-(A-S))`; `T=max(P-C-R,0)`. `B`, source IDs, fee transaction ID, amount, currency, mode and digest are immutable. If fee missing/unsettled/malformed/wrong currency or provider changes a frozen fee, enter reconciliation, refuse reservation and make no numeric receivable. If `R>P-C`, consume `P-C`, record receivable `R-(P-C)`, and terminal `T=0`; never reduce commission or create a zero/negative Transfer.

**Lock order:** any freeze, refund, dispute, offset, reservation or dispatch that may touch seller debt locks `seller_receivable_accounts(seller_id) FOR UPDATE` **before** `lock_order_money`'s order/transaction/state/payment/refund locks (`app/services/order_money_service.py:785-820`). Create the account row with conflict-safe insert before locking. No path acquires these in reverse. `remaining_payable_cents=max(P-C-R-seller_receivable_offset_cents-seller_refunded_cents-seller_payout_posted_cents,0)`, with refund recovery accounting separately for already discharged `R` and offset. Before refunds/offsets/payout, this is `T`. If `R>P-C`, the debit to 2110 is capped at its available payable and the excess is a ledger receivable.

`reserve_order_payout` (`app/services/order_money_service.py:1010-1053`) refuses if fee not frozen, refund/dispute/reconciliation pending or seller-debt reconciliation unresolved. Under both locks, apply **one atomic offset PER PAYOUT against the remaining balance**, oldest receivable first, up to current `T`, posting DR 2110 / CR 1210 and recording per-entry offsets. Then hash `amount=remaining_payable_cents`, charge `source_transaction`, destination and idempotency key; if zero, set a durable no-transfer terminal state/reason and never call Stripe. `validate_payout_request` (`app/services/order_money_service.py:953-985`) independently derives the frozen post-offset amount and checks offset rows, digest and charge. `dispatch_order_payout` (`app/services/order_money_service.py:1153-1213`) reacquires seller lock first, checks provider refunds, fee snapshot, debt balance, reservation revision and all payout guards before sole `Transfer.create`. A dispatching/unknown request never gets rekeyed or offset again: reconcile provider outcome. `finalize_order_transfer` (`app/services/order_money_service.py:1074-1122`) journals only actual request/Transfer amount and increments posted cents by that amount; retry validates the original fee snapshot and request. Revise the current `seller_amount_cents` request/finalization assumptions (`app/services/order_money_service.py:946,964,1085-1099`). `T=0` is an auditable terminal outcome, not a succeeded Stripe Transfer.

**Refunds:** Keep platform refund admission (`app/services/refund_processing_service.py:363-429`) and provider-refund refusal (`app/services/order_money_service.py:862-897,1175-1189`). Excess `E` is a buyer refund first. Thereafter `B_net=B-E`; allocate a partial listing-price refund by cumulative integer ratio, `fee_return_total=floor(B_net×cumulative_P_refunded/P)` except the final refund receives the exact remainder. A full refund makes cumulative buyer refunds exactly `P+B`; reverse 4040 buyer recovery only for buyer-fee cents actually returned and recognize matching seller recovery. The original `A` remains owed. Before reservation, recalculate payable after refund under both locks; unpaid principal/fee goes to receivable. After reservation but before dispatch ownership, cancel/rebuild the request with the new refund/offset, preserving its idempotent revision protocol. After dispatch ownership, do not rekey; reconcile or reverse Transfer if authorized/available, then book unrecovered principal and retained fee as seller receivable. Existing refund allocation uses 5100 when payable is insufficient (`app/services/finance/engine.py:258-288`; `app/services/refund_processing_service.py:543-564`): reclassify to 1210 with a distinct source ID, never leave 5100 as the seller debt. Recovery order is this order's available payable, then same-seller later payouts. Duplicate/out-of-order source events produce one ledger row and journal.

**Operator hold answer:** `order_money_service.py` has **no explicit operator-hold flag**; `order_money_states` has payout/reconciliation state and reason, but no operator-hold column (`app/models/order_money_state.py:9-40`). Use existing `reconciliation_required`/`reconciliation_reason` and payout refusal (`app/services/order_money_service.py:880-885`) for an operator-initiated refund, dispute or fraud review; record reason and authorized release. The ordinary clock remains 48 hours after confirmation (`app/services/order_money_service.py:834-847,914-923`). Contractual hold up to 90 days does not add a 90-day timer or automatic release.
