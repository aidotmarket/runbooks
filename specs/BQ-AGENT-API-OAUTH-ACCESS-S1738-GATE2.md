## 1. Outcome and decisions

A buyer-owned, explicitly agent-enabled OAuth client exchanges its own secret for one `type=oauth_access`, `aud=oauth_agent` bearer and calls protected `/api/v1/agent/*` routes without an agent key. The actor is the client owner/buyer, bound organization and current server-side policy. The same selected actor controls scope, rate budget, spend reservation, legal acceptance, transaction attribution and audit. An existing agent key continues through its existing path. No generic web JWT, refresh token, AIM Data token or legacy `type=agent/aud=agent` token gains Agent API authority.

Ship `client_credentials` only. Remove authorization-code and refresh-grant claims from this Agent API quick start and the mounted token endpoint description; their implementation remains outside this release. The mounted `/oauth/token` delegates non-AIM grants to the confidential client-credentials handler today, while its prose advertises unsupported grants [backend@d9b02a5c:app/api/v1/endpoints/oauth.py:356-399]. Current client-credentials tokens carry `type=agent/aud=agent`, whereas the wallet verifier requires `oauth_access/oauth_agent` [backend@d9b02a5c:app/services/oauth_client_service.py:147-181; backend@d9b02a5c:app/services/oauth_service.py:340-379]. Gate the new token shape and its admission with the same flag. Old token shape remains valid only for its existing consumers and never becomes an Agent API bearer.

**Owner cap rule:** an authenticated owner may lower or set a client cap only within a server-configured administrative ceiling; initial cap and ceiling are zero until an authorized admin assigns a nonzero ceiling to that client. An owner cannot raise the ceiling, enable paid scope or transfer client ownership. The admin operation requires existing admin authorization and an audit reason. This supplies a bounded self-service path without granting an unreviewed paid allowance at client creation.
