## 3. D1/D2: visibility, projection and public discovery

**One visibility seam.** `ListingSearchService.search` currently gathers lexical candidates, Qdrant IDs and PostgreSQL hydration before dedup/page (`app/services/listing_search_service.py:304-320, 427-450`); the SQL filter checks only `status='published'` (`:816-831`). Implement `ConnectorListingVisibility` as a reusable SQLAlchemy/SQL predicate used inside lexical candidate selection, Qdrant ID hydration, SQL fallback and counts. It requires published, `is_listed`, and a current bound licence snapshot whenever `LISTING_LICENSES_ENABLED` requires one, matching the semantics of `app/services/public_sample_service.py:76-100, 122-129`. Qdrant filters only narrow candidates; PostgreSQL is the authority. Do not post-filter a page. Refill bounded candidate windows or use a connector-specific eligible query so `offset`, `has_more` and any returned `total` describe eligible results. For pages beyond the 500-candidate window, D2 uses a connector-specific eligible SQL query for the whole request, ordered by `published_at DESC, id DESC` before offset/limit; `has_more` and any `total` use the same eligible set. When complete/cheap total cannot be proved across the hybrid window, omit `total` rather than report a partial count. Return `search_mode=hybrid|lexical|sql_fallback`; preserve the stable degraded-search alert and add a mode metric (`listing_search_service.py:453-470, 794-813`). Cap `limit` at 50, default 20, and `offset` at 1000; a deeper page is `INVALID_ARGUMENT`, never a huge Qdrant window. Do not inherit web search's price facets (`listing_search_service.py:700-730`) or price filters. No org or seller identity is selected from caller arguments.

**Projection.** `ConnectorPublicListingProjection` accepts only eligible rows and allowlists Gate 1 §3 fields. `ListingService.get_by_id` returns `SELECT *` (`app/services/listing_service.py:142-150`), so never serialize that dict directly. Do not call `GET /listings/{id}`: it updates `view_count` (`app/api/v1/endpoints/listings.py:410-461`). Do not pass through its JSON-LD schema/download `contentUrl` (`:490-533`), owner-only preview (`:609-621`), private quality/verification/compliance conclusions (`:465-484`), seller ID, storage references or source bytes. Detail eligibility uses the same visibility predicate as search, and every ineligible ID gives indistinguishable `NOT_FOUND`. Use the approved public seller display name only when a typed verification/approval/opt-in record proves it at request time; otherwise `ai.market Seller`, per identity policy. No personal contact or direct links.

Schema defaults to redacted columns and coarse statistics; `preview.kind=schema_stats` or `none`. `app/api/v1/endpoints/mcp_marketplace.py:108-139` suppresses PII values but retains PII column names. Replace a flagged or heuristic email/address/date-of-birth name with `redacted_column_<output-position>`; no source-name hash, inferred labels or PII values. Cap allowed column names/types at 80/40 characters and 50 columns; drop or bucket low-count distributions below five. An inline sample remains absent unless current seller web opt-in, current public-sample/licence/version/approval gates and a safe bounded projection are all proven. If implemented, it is ≤5 rows and ≤2 KB **after JSON serialization**, separately contact-scrubbed and never sent to allAI. Public sample asset availability (`app/services/public_sample_service.py:122-183`) alone is insufficient permission to include bytes. D2 can ship with `preview.kind=schema_stats|none` and no sample rows.

**Contact scrubber.** Reuse the detector decision path `normalize_for_detection` → `MediationService._pre_check` → `has_contact_patterns`/`ambiguous_spans` (`app/services/request_publication_service.py:151-178`). It is a verdict, not redaction. The offset map returned by `app/utils/text_normalization.py:normalize_for_detection` is documented approximate and must not be reused as-is; D1 builds a full reversible normalized-to-original map or fails closed. `MediationService._pre_check` is private and returns definite signals as strings only; D1 re-runs its shared `PATTERNS` definitions to locate definite email, phone, URL and direct-contact spans, pinning those pattern definitions as the stable dependency. Replace definite spans with `[contact removed]`, count redactions without logging raw input, and re-run the detector on the result. For an all-contact required field use a fixed safe summary; omit an optional field. Ambiguity, detector outage, incomplete localization or residual contact yields fixed safe summary or `TEMPORARILY_UNAVAILABLE`, never original text. Run it before projection, before model prompt composition, after model output and before rendering both output channels. Coverage includes search and detail title/summary/description/schema names, opted-in branding/sample, buyer request title/summary/categories, notification summary, user question and model answer. Cap each item and nested string by field; render only from the already safe structured projection, with max 8 KB serialized JSON and 2 KB text per tool result. Text never adds a URL, identity or unprojected field.

`search_listings` implements Gate 1's query/category/privacy-score inputs and `read+search` classes. `get_listing` accepts only `listing_id` and uses `read`. For `openai`, remove price, range, tier/type, purchase link and purchase language **before** any public projection is rendered; if authored title/summary/schema text contains a price or purchase solicitation, replace that field with a fixed neutral summary or omit it and test both output channels. Do not rely on an MCP client choosing to hide fields. Claude/default may receive Gate 1's allowed `price` only. All seller-authored strings remain marked `x-untrusted` even after scrub.

## 4. D3: personal activity and requests

`get_activity` accepts only 20-default/50-max `limit` and `offset≤1000`, with no user/org selector. `NotificationService.list_for_user/count_for_user` filters by `user_id` (`app/services/notification_service.py:145-175`), but the model has no organization key and contains raw `body`, `metadata` and `link_url` (`app/models/notification.py:18-27`). A **personal grant** returns an owner-filtered page projected to `{id,kind,occurred_at,summary,state?}`; derive `summary` only from a safe, allowlisted notification type/title and scrub it. An **org grant** returns an empty page until a typed event-to-grant-org association exists and is tested; never infer org from payload or URLs. Storage failure is `TEMPORARILY_UNAVAILABLE`, not an empty feed. Action-path events can join after their own owner-filtered table and tests exist, without changing this handler's contract.

`list_data_requests` accepts `view=mine` only, optional bounded category/query and the same 20/50/1000 paging. The existing `list_requests(owner_id=...)` uses `eligible_or_owner_predicate`, which also returns other public requests (`app/services/data_request_service.py:191-250`); never call it for `mine`. A new query requires `DataRequest.buyer_id == principal.user_id`, applies safe filters/count/page in one owner-scoped query and projects only Gate 1 §3 fields, including the owner's safe unpublished states. The pinned model has `buyer_id` and nullable `party_id` but **no typed org ID** (`app/models/data_request.py:70-99`), and `create_request` writes no org binding (`app/services/data_request_service.py:128-175`). Thus a personal grant can return the owner's rows; an org grant returns an empty page until a reviewed typed request-to-org binding exists. Do not treat `party_id`, current membership, a title/payload or ownership alone as historical proof that a request belongs to the grant org. This is a conservative consequence of Gate 1's owner **AND** grant-org rule, not a new matching/public feed. A reviewer account can exercise `mine` with a personal `account.read market.read` grant; capture the org-grant empty case separately. `public` and `matching` arguments are `INVALID_ARGUMENT`.

## 5. D4: allAI budget, usage and neutral answer

**Postgres is the authority.** Core Redis rate limiting allows per-process read fallback during outages (core Gate 2 §5); that is unsuitable for a connector-wide dollar cap. D4's additive migration creates `connector_allai_daily_budget(day_utc date PRIMARY KEY, reserved_microusd bigint NOT NULL DEFAULT 0, charged_microusd bigint NOT NULL DEFAULT 0)`, `connector_allai_daily_calls(day_utc,user_id,client_id,accepted_count, PRIMARY KEY(day_utc,user_id,client_id))`, and `connector_allai_reservations(id UUID PRIMARY KEY, day_utc, user_id, client_id, model_policy_hash, reserved_microusd, charged_microusd NULL, state, created_at, reconciled_at NULL)`. Nonnegative checks and an index on `(day_utc,state)` are required; no prompts, questions or answers in these tables. Use integer micro-USD and round each worst-case/actual charge **up**. The migration's `down_revision` is the actual single head after core/OAuth and any intervening migrations, verified at build time, not the older Gate 2 example head.

In one short real-Postgres transaction, lock the day row first (`INSERT ... ON CONFLICT DO NOTHING`, then `SELECT ... FOR UPDATE`), lock/upsert the user/client/day counter, reject at the configured `CONNECTOR_ALLAI_CALLS_PER_USER_CLIENT_UTC_DAY` accepted calls or if `charged + reserved + new_max` exceeds configured `CONNECTOR_ALLAI_USD_PER_UTC_DAY` converted to integer micro-USD; validate those settings at ≤20 calls and ≤USD 5. Then increment accepted count/reserved and insert a unique reservation. A rejection consumes neither calls nor dollars. Release the transaction **before** provider I/O; no database lock spans the model call. UTC date is assigned once at reservation and reconciliation uses that same day even across midnight. Commit/serialization/deadlock/store failure denies the call. A distinct idempotent reconciliation transaction locks the same day row, locks reservation, verifies it is pending, subtracts its reserved amount, adds actual usage charge ≤ reservation, marks settled and commits. Duplicate reconciliation is a no-op; a conflicting or impossible result disables `ask_allai` and alerts. Never credit a failed/ambiguous/timeout call without authoritative final usage: conservatively settle at full reservation (or leave pending counted as reserved until reconciled); aged pending reservations remain counted and require operator reconciliation, never automatic refund. Test restart and parallel workers on real Postgres, including the final cent and midnight. The core `read` limiter still applies first; this is an additional `allai_query` guard, not a core rate-class edit.

`CONNECTOR_ALLAI_MODEL` pins the sole allowed initial model. `CONNECTOR_ALLAI_FALLBACK_MODELS` defaults to empty; enabling any fallback requires a listed model/price/hard-bound fixture. Before a call, reserve the **sum of the worst-case charge of every reachable attempt**: the primary, each enabled fallback and every automatic retry of any of them. `app/core/llm.py:78-87, 420-446, 477-485, 510-528` exposes `LLMChatResponse` with Gemini input/output/thinking and Anthropic input/output, but no normalized cache token fields; `AllAIResponderService.try_auto_answer` returns only answer/confidence/escalation (`app/services/allai_responder_service.py:140-203`). Add a connector-only bounded responder returning actual provider model ID, provider and all billable usage fields to D4. Extend `LLMChatResponse` with cache write/read and any provider-specific billable fields, preserving existing callers. Missing model identity, any billable usage category, price, hard bound, or reconciliation keeps the full reservation charged and the tool disabled pending repair. `max_tokens` is not enough by itself for Gemini: the wrapper increases output allowance by `GEMINI_THINKING_BUDGET` (`app/core/llm.py:35-40, 460-485`). The builder must prove an end-to-end provider-enforced input/output/thinking/cache/retry bound for the selected model and include it in max-cost math. If that bound cannot be proven, D4 deploys killed. No automatic fallback through an unpriced model.

Build the prompt only from the D1 public metadata projection and scrubbed bounded question, with no sample rows, hidden listing metadata, platform pricing text or seller-escalation side effect. The existing responder's `PLATFORM_KNOWLEDGE` and context explicitly mention commission, purchase and pricing (`app/services/allai_responder_service.py:96-106, 330-334`), so do not call `try_auto_answer` or reuse those prompt constants. Use a neutral connector prompt variant and strict structured result `{answer≤2000,confidence 0..1,sources:[allowlisted public metadata keys],needs_seller}`. `needs_seller` says the public metadata cannot answer; it creates no inquiry. A price/purchase-oriented OpenAI question receives the fixed neutral refusal **before** model invocation. If any OpenAI model answer mentions numeric/currency price, range, pricing model, purchase URL or purchase prompt, replace it with that same fixed refusal in both channels. The answer is `x-untrusted`; contact-scrub after generation. The legacy MCP handler inserts `mcp_conversations` and `mcp_messages` (`app/api/v1/endpoints/mcp_marketplace.py:386-460`); D4 never invokes it and tests spy on all domain writes. Core audit and D4 budget writes are allowed.
