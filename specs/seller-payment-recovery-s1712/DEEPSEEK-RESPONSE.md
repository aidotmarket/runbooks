## SIMPLER

Within the disclosed five-target boundary I found **no** simpler alternative that also keeps the 23 h create window for a worst-case 500-item backlog — the continuation chain is what makes 500 items fit inside the window, so removing it converts the tail into expired evidence-only items, which is a real requirement failure rather than a simplification.

The closest genuine simplification, recorded as **advisory only**: keep the pass ceiling but drop the continuation machinery (the 60 s continuation enqueue, the recovery-only flag that skips legacy cleanup, the enqueue-failure backstop path, and the 19/30 s/600 s reservation arithmetic with its continuation-delay capacity model) by changing the *existing* schedule entry's cadence in `app/core/celery_app.py:238` from `crontab(minute=20)` to e.g. `crontab(minute="*/15")`. That removes roughly one code path plus its continuation/backstop test family, and 4 passes/hour × 19 candidates places 500 items in ≈6.6 h — still inside 23 h. Cost: ~4× baseline background load (mitigated by the shared cursor's documented overlap refusal), and it touches `celery_app.py`, which is outside the five disclosed targets, so it would need its own scope disclosure before it can be adopted. Rollback: revert one string. Not a mandate.

## BETTER

**Advisory, evidence-based alternative:** trigger recovery from the failure itself instead of only scanning for it — persist the original attempt's recovery obligation in the same transaction that commits the prepare record (in `transaction_service.py`, already a prior-32 target, using the already-bound `agent_audit_log`), and keep the hourly scan only as the legacy/backstop path. Failure modes: a crash between prepare-commit and any explicit enqueue still leaves the scan as the only recovery route, and the design would carry two admission paths instead of one, so it is more code, not less. Cost: materially better window margin (seconds-to-minutes recovery per lost response rather than up to ~5 h of queued passes), and it removes the fairness/starvation pressure that the cursor ordering, 19-slot ceiling and continuation chain exist to manage. Rollback: disable the enqueue write and the scan alone resumes authority — no money semantics change, since both paths funnel into the same binding/completion transaction. It is not a mandate: the current design already satisfies the retained 23 h window and the no-new-table constraint, and the current text honestly bounds its own throughput.
