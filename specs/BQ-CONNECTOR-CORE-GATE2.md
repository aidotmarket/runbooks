## 3. Cross-spec contract

`app/mcp/connector_shared/` is key-free and imported by the resource, AS, and main backend. It owns `contracts.py` with the exact Gate 1 §5.3 interfaces below, `grants.py` with **both** `revoke_grant` and `revoke_all_for_user`, `profiles.py`/`profiles.yaml`, `scopes.py`, `audit.py`, `oauth_models.py`, and `oauth_store.py` with create/replace grant and single-use consent-ticket functions. `oauth_store.py` must not define either revocation hook. `app.mcp.connector` and `app.main`/`app.api`/`app.services`/`app.actions` may import shared but never `app.mcp.connector_auth`; AS may import shared but never resource; shared imports neither. Static AST and fresh-process import tests enforce this. Only `ai-market-connector-auth` has `CONNECTOR_OAUTH_SIGNING_KEYS`; `ai-market-connector` and backend refuse or fail the pre-enable variable-name check if it is present.

```python
@dataclass(frozen=True)
class VerifiedToken:
    user_id: UUID; client_id: str; grant_id: UUID; token_jti: str
    scopes: frozenset[str]; issuer: str; audience: str; expires_at: datetime

class TokenVerifier(Protocol):
    async def verify(self, token: str, *, resource: str) -> VerifiedToken | None: ...

@dataclass(frozen=True)
class Grant:
    grant_id: UUID; user_id: UUID; org_id: UUID | None; client_id: str
    scopes: frozenset[str]; profile: Profile; revoked_at: datetime | None

class GrantStore(Protocol):
    async def load_active_grant(self, grant_id: UUID) -> Grant | None: ...
```

Construct `VerifiedToken` with keyword arguments; `token_jti` is the JWT `jti` and fourth declared field. The verifier returns `None` for invalid ES256/issuer/audience/expiry/jti; the resource then checks token/grant user, client, scopes and live org membership on every request (personal grant means no active membership). No grant cache in P0. Fakes implement both protocols before the AS implementation lands; the same contract suite runs with fakes and with OAuth's real verifier/store. Canonical issuer `https://auth.ai.market`, audience/resource `https://connect.ai.market/mcp`, public JWKS `https://auth.ai.market/.well-known/jwks.json`; no `/mcp/openai` alias. Scope filtering uses all required scopes. A DCR client is always `default`; elevated Claude/OpenAI profiles require validated allowlisted CIMD identity, pinned document hash and matching redirect, with downgrade of live grants on drift.

Foundation means Chunk 0 deployed, then one shared additive revision `s_connector_foundation_001` creating `connector_switches`, `connector_audit_events` and `connector_review_queue`, shared profile/scope catalogue and interfaces/fakes/contract tests, both Railway JSON files, A23 isolation check, and the health-only `app/mcp/connector_auth/asgi.py` stub. Backend web owns migration execution; neither new service migrates on startup. The auth service is configured with both flags off only after this inert foundation. OAuth revision `s_connector_oauth_001` depends on the foundation revision, is additive, and its downgrade retains all five OAuth tables.

`connector_audit_events` is the sole connector audit table, append-only and retained pending legal sign-off. The fixed `event_type` CHECK catalogue is `tool.call`, `http.auth_failure`, `oauth.grant_created`, `oauth.grant_superseded`, `oauth.grant_revoked`, `oauth.grant_downgraded`, `oauth.refresh_reuse_detected`, `oauth.registration_created`, `action.confirm`, `action.decline`. Tool-call fields are nullable for OAuth/HTTP rows; `tool.call` requires tool/user/grant/client/args HMAC and is unique by request id. Writers use `AuditSink`; `record_required` joins a write effect's transaction. `tests/connector/test_audit_contract.py` inserts one valid row for every event type and rejects a duplicate tool call. Action-path uses this table after foundation and does not extend `agent_audit_log`.

## 5. Resource request and tool behavior

Middleware order: 256 KB body limit → exact Host/Origin and trusted proxy peer check → request/trace id → pre-auth IP limiter → env/DB global switch → bearer verification → live grant/org/profile → low-level MCP transport → shared list/call predicate → tool limiter → audit. `POST /mcp` only, stateless 2025-11-25; GET 405, batch rejected, unrelated `/mcp/*` 404. `/healthz` has no dependency; `/readyz` checks DB, Redis and connector tables. RFC 9728 PRM at `/.well-known/oauth-protected-resource` and `/mcp` variant advertises only the canonical resource and AS. Unauthenticated `initialize`, `tools/list`, `tools/call` get 401 with `resource_metadata` and no names; unknown/hidden tools never leak in list. Check `scopes_required ⊆ principal.scopes` at both list and call; a visible but under-scoped tool gets HTTP 403 `insufficient_scope`, a hidden/disabled tool gets the Gate 1 §5.7 tool-result error. Registry lint requires input/output schemas, existing nonempty scopes, explicit effect/annotations, idempotency for writes, at most 20 per profile, default read-only, no P0 `scopes_any_of`.

Redis limiter uses one Lua transaction that removes old entries, tests count before inserting, then sets expiry; a rejection consumes no quota. Gate 1 §5.8 values: pre-auth IP 60/min, read 120/min/user, write 20/min/user, search 600/hour per client/user, outreach 30/day per org, offers 50/day per org (latter classes inert until later BQs). Key dimensions include user, org or personal-user fallback, client, and class. Third burst in 24 h writes one review row and halves read/write limits for 24 h, with no automatic suspension. Bounded Redis pools wait ≤100 ms; outage/exhaustion uses a per-process read fallback (`limit/expected_processes`), while writes fail closed. Switch cache ≤5 s; env floor wins; cold DB failure disabled. `/mcp` must not start if the signing-key environment variable exists.

`get_my_account` reads only the principal's user and active grant org, returns Gate 1 §5.12 `{user, organization|null, connection, seller, negotiation_limits:null}` shape. Audit emits one `tool.call` per call, HMACs of canonical JSON args/result (never raw content), aggregated `http.auth_failure`, and allowed trace attributes only. A failed read audit insert logs/counts and still returns; future writes use `record_required` in their effect transaction. Error shapes and retry channels are exactly Gate 1 §5.7; implement table-driven assertions rather than ad hoc exception text.
