# BQ-RUNBOOK-DISCOVERY-TIER-S1482 — Gate 2 implementation specification

Repo: `aidotmarket/runbooks` (single repo; no other repo is touched)
Base: `main` @ 280d701
Author: mars / S1482
Origin: Max directive, 2026-08-08. "Get the runbooks indexed in a way that is super easy to find and update."

## 1. Problem, stated as measured facts

1. The repo holds two populations of runbooks:
   - 21 files under `runbooks/`, conformant to the §A–§K standard, fully indexed in `CATALOG.json` and rendered into `TOPIC-ROUTER.md`.
   - 83 files at repo root, legacy format, indexed nowhere.
2. `runbook_tools/catalog/model.py:98-99` raises `CatalogError` unless `frontmatter["status"] == "ACTIVE"`, and `canonical_active_path()` (same file, line 29) hard-codes the only admitted path as `runbooks/{runbook_id}.md`. A root-level, non-conformant runbook therefore cannot appear in the catalog at all.
3. `TOPIC-ROUTER.md` carries the banner `Generated by runbook-catalog. DO NOT EDIT.` and states `CATALOG.json` is the sole machine authority. Because the catalog admits only ACTIVE members, the router presents 21 of 104 runbooks.
4. `scripts/router_drift_check.py` already asserts "every runbook .md at repo root is referenced in TOPIC-ROUTER.md". Run today it prints `ROUTER DRIFT CHECK: FAIL` and lists all 83 — **and then exits 0**. Nothing in the repo invokes it (grep across yml/yaml/py/sh/toml returns only the file itself).
5. Consumer safety, verified: `koskadeux-mcp/tools/runbook_ref.py` resolves a `RunbookRef` by testing that `runbooks_repo / ref.path` exists on disk (lines 176-198, 243). It does not read `CATALOG.json` and does not test `status`. Catalog membership is therefore a DISCOVERY surface for the session gates, not an authority gate.

Consequence: cost is paid in repeated rediscovery. In S1482 the operator consulted the router at session open, the router did not surface `schema-migration.md`, and the operator then committed the precise error that runbook's §S.7 documents verbatim ("Hand-rolled head detection lies... always run the real `alembic heads`"), and reported it to Max as a finding.

## 2. Goal and non-goals

GOAL: every runbook in the repo is discoverable from the catalog and the router, without any runbook being rewritten.

NON-GOALS (do not do these):
- Do not rewrite, reformat, or lint-fix any of the 83 root runbooks.
- Do not relax, reorder, or skip any of the 21 lint checks in `runbook_tools/lint/checks.py`.
- Do not change what it takes to become ACTIVE.
- Do not move or rename any runbook file.
- Do not modify `koskadeux-mcp`.

## 3. Design: two tiers, one catalog

Introduce a second, deliberately minimal membership tier.

| | ACTIVE (unchanged) | LISTED (new) |
|---|---|---|
| Source path | `runbooks/{id}.md` only | repo-root `{id}.md` only |
| Frontmatter required | all `REQUIRED_ACTIVE_FIELDS` | none |
| `authoritative_for` | >= 1 row, required | MUST be empty |
| `error_signatures` | permitted | MUST be empty |
| Appears in `indexes.topics` / `.aliases` / `.error_signatures` | yes | NO |
| Appears in `TOPIC-ROUTER.md` | yes, existing Topics table | yes, in a NEW separate table |
| Can satisfy an authority/section claim | yes | no — it declares none |

A LISTED entry asserts one thing only: this runbook exists, at this path, and here is its title. It never claims authority, so it cannot be mistaken for it.

## 4. Changes, file by file

### 4.1 `runbook_tools/catalog/model.py`
- Add `LISTED_STATUS = "LISTED"` and `def canonical_listed_path(runbook_id: str) -> str: return f"{runbook_id}.md"`.
- Add classmethod `CatalogEntry.listed_from_file(path: str, title: str) -> CatalogEntry` constructing an entry with: `runbook_id` = kebab-validated file stem; `path` = `canonical_listed_path(runbook_id)`; `status="LISTED"`; `domain="unmigrated"`; `owner="unassigned"`; `last_verified_at=None`; empty `authoritative_for`, `error_signatures`, `aliases`, `supersedes`, `superseded_by`; `authority_admission=False`; `action_authority_eligible=False`; `semantic_verification=False`.
- `from_frontmatter` is UNCHANGED. Its `status != "ACTIVE"` raise stays exactly as it is. LISTED entries never pass through it.
- Serialisation: `as_dict()` for a LISTED entry emits `runbook_id`, `path`, `status`, `title`, `domain`, `owner`, and empty lists for the collection fields, so the JSON shape stays uniform for existing readers.
- `title` is the text of the file's first `# ` heading, stripped; if absent, fall back to the `runbook_id`. Bound it with the existing `_bounded_string` at `MAX_SECTION_BYTES`.

### 4.2 `runbook_tools/catalog/generator.py` (`build_catalog`, line 219)
- After ACTIVE members are assembled, scan repo-root `*.md`, excluding `README.md` and `TOPIC-ROUTER.md`.
- Skip any stem already present as an ACTIVE `runbook_id` (ACTIVE always wins; never emit both tiers for one id).
- Emit a LISTED entry per remaining file, sorted by `runbook_id`.
- `indexes.topics`, `indexes.aliases`, `indexes.error_signatures` are built from ACTIVE entries ONLY. This is the load-bearing separation — assert it in tests.
- Bump `schema_version` 1 -> 2.

### 4.3 `TOPIC-ROUTER.md` rendering
- Existing `## Topics` table: unchanged, ACTIVE only, byte-identical output for the current 21.
- Append a new section:

```
## Unmigrated runbooks (discovery only — not standard-conformant, no authority)

These are findable but have not been rewritten to the §A–§K standard. Treat the
content as informative, not authoritative. Promote one by migrating it to
`runbooks/<id>.md` with full frontmatter; it then moves into the Topics table above.

| Runbook | File |
|---|---|
| <title> | [`<id>.md`](<id>.md) |
```

- Root links are bare `<id>.md`, matching the working `builder-controls.md` rows and NOT the `runbooks/<id>.md` form used for ACTIVE members.

### 4.4 `scripts/router_drift_check.py`
- Fix the exit code: the function already builds a failure list and prints `ROUTER DRIFT CHECK: FAIL`; it must `return 1` on any failure. Today it returns 0, so the guard can never fail a caller. Preserve all existing check logic and output text.
- Add `--json` emitting `{"ok": bool, "failures": [...]}`.

### 4.5 Wiring (this is what stops it regressing)
- Add `make check-runbook-index` (or the repo's existing task-runner equivalent — inspect before inventing one) running: catalog generation into a temp dir, byte-diff against the committed `CATALOG.json` and `TOPIC-ROUTER.md`, then `router_drift_check.py`. Non-zero on any difference or failure.
- Wire it into the repo's existing CI workflow if one exists; if none exists, state that plainly in the build report rather than creating CI infrastructure under this spec.

### 4.6 Regenerate
- Regenerate `CATALOG.json` and `TOPIC-ROUTER.md` and commit them.

## 5. Acceptance criteria (all must hold)

1. `CATALOG.json` contains 104 entries: 21 `status=ACTIVE`, 83 `status=LISTED`. No id appears twice.
2. The 21 ACTIVE entries are byte-identical to their current form except for the `schema_version` bump.
3. `indexes.topics`, `indexes.aliases`, `indexes.error_signatures` reference ZERO `LISTED` runbook_ids. Assert by test.
4. `python3 scripts/router_drift_check.py` prints PASS and exits 0.
5. Deliberately breaking coverage (delete one router row) makes it exit non-zero. Assert by test — this is the regression that produced today's state.
6. `TOPIC-ROUTER.md` contains a row for every one of the 104, and `grep -c "schema-migration" TOPIC-ROUTER.md` is non-zero.
7. Every existing test under `tests/` passes unchanged. Where a test asserts a catalog count or `schema_version`, update the expectation only — never the assertion's intent.
8. No file under `runbooks/` and no root `.md` runbook has its content modified. `git diff --stat` shows changes only to `runbook_tools/`, `scripts/`, `tests/`, `CATALOG.json`, `TOPIC-ROUTER.md`, and the task-runner/CI file.
9. A LISTED entry cannot satisfy an authority claim: add a test asserting `listed_from_file(...).authoritative_for == ()` and that resolver/search authority lookups never return a LISTED entry.

## 6. Risk

Blast radius is the runbooks repo plus the session-open boot payload, which pins `CATALOG.json` by SHA (`catalog_ref` in the boot kernel). A malformed catalog would break session boot for BOTH instances. Mitigations: `schema_version` bump makes the change explicit; ACTIVE entry shape is preserved byte-for-byte; the JSON shape stays uniform; and `runbook_ref.py` never reads status, so gate behaviour is unaffected by construction. Reviewers should confirm point 3 above most carefully — it is the only place where a mistake could let an unmigrated runbook be treated as authoritative.
