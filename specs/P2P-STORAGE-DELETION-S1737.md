# Delete ai.market's seller-data storage and relay code (S1737)

**Authority:** Max, 2026-09-22, S1737: "simplify code whenever possible to not be additive" (Event Ledger `109db5e8`), then, on the proposal to delete rather than guard: "Then do it" (`87fb454b`). Rule: `runbooks/data-delivery-p2p.md`. Risk class: customer data and delivery, so unanimous Council (GLM, DeepSeek, Gemini) on this spec and on the build.

**Base:** ai-market-backend `main` after PR #451 (S1735 licence chunk C) merges; citations below are to `6acf09761a08a6b97ceede1f0705567df3bc0e05` and, where marked, to the #451 head `f046bfc16d301cea9cf6062fae93eb8193ae3eca`. MP builds on `build/p2p-storage-deletion-s1737`.

## Principle

Delete every module whose purpose is to receive, buffer, stage, store, presign, proxy or relay seller bytes through ai.market, plus everything that exists only to serve those modules. Where a surviving caller branches into removed code, delete the branch so the flag-off behaviour becomes the only behaviour. No replacement abstractions, shims or new flags. The one exception is code that a surviving live path needs; it is named below.

## Keep

- The manifest contract for the future peer-to-peer design (Mars, peer message 5843): `listing_version_members`, `manifest_hash`, manifest intake and validation in `vz_publish` / `vz_publish_service.py`, `listing_summary.py`, `listing_versioning.py`, and `MULTI_FILE_DATASETS_ENABLED`, which afterwards gates only manifest publishing and stays off. The per-file grant/consume semantics and buyer-side hash check are the contract to rebuild peer to peer; their bucket-bound implementation goes.
- The live legacy delivery path (`fulfillment_listener_service.py` stream-to-disk, `delivery_service.py` `_queue_delivery_request`). It is how AIM Data orders deliver today; it goes under T-2026-000839 once a peer-to-peer replacement exists.
- Seller Workspace delivery from the seller's own bucket (`order_service` `assume_seller_role`, `seller_workspace_delivery`, `seller_workspace_r2.py`).
- Every #451 licence gate on a surviving door.

## Two releases

Release 1 is the code deletion with **no schema change**: model attributes for the dropped columns go, the database columns and the nine tables stay (SQLAlchemy ignores unmapped columns). Release 2 is only the migration, merged after release 1 is live and Railway shows no deployment of the previous image still running for `ai-market-backend`, the Celery worker or beat. So no process ever runs code that references a dropped object, and the migration never races old code.

## Migration (release 2)

One revision, one transaction, run by `scripts/run_alembic_startup.sh` before uvicorn. Release 1 code never reads or writes any object below, so the only concurrent locks are ordinary row locks on the live tables.

1. `SET LOCAL lock_timeout = '5s'`. If it times out the deploy fails cleanly and is retried; nothing is half-applied.
2. Refuse (raise, naming the table and predicate) if any of: a row in `order_staging`, `transfer_session_members`, `transfer_chunk_receipts`, `transfer_part_receipts`, `order_delivery_members`, `buyer_download_meter`, `listing_sample_assets`, `seller_sample_assets`, `listing_asset_tombstones`; `aim_nodes` with `relay_mode` or `relay_registered_at IS NOT NULL`; `aim_sessions` with `connection_mode = 'relay'`; a non-null value in any shared column listed above, or `transfer_sessions.completion_state <> 'none'`. (Plain reads; release 1 cannot write these values, so the check cannot be raced.)
3. Drop the `listing_asset_delete_tombstone` trigger, then `retain_listing_asset_key()`.
4. Drop tables children first: `transfer_part_receipts`, `transfer_chunk_receipts`, `transfer_session_members`, `order_delivery_members`, `buyer_download_meter`, `order_staging`, `listing_sample_assets`, `seller_sample_assets`, `listing_asset_tombstones`. No `CASCADE`.
5. Alter live tables in the order the application locks them (`fulfillment_listener_service.py` takes `orders` before `transfer_sessions`), each table's index, constraint or FK before its columns: `orders.delivery_manifest_hash`; `transfer_sessions` index `uq_transfer_manifest_receiving_order`, constraint `ck_transfer_completion_state`, then `manifest_hash`, `staging_generation`, `completion_state`, `completion_lease_until`; `fulfillment_download_tokens` FK `fk_fulfillment_grant_version`, then `manifest_hash`, `purchased_version_id`; `aim_nodes.relay_mode`, `aim_nodes.relay_registered_at`. `aim_sessions` is only read.

Downgrade raises: every dropped object was empty or null, and undoing the code would be a forward migration, not a restore. Tests: the empty, null, direct-only state upgrades; each refusal predicate refuses.

Production state read by Vulcan 2026-09-22 (procedure step 3 in `runbooks/data-delivery-p2p.md` prints the table and relay counts): all nine tables 0 rows, `aim_nodes` 2 rows with 0 relay, `aim_sessions` 0 rows, every shared column null. Re-run immediately before merge.

## Build rules

Report every remaining `git grep` hit in `app` and `scripts` for a removed module or symbol and why it stays. Run the full backend suite and report exact counts. Check `ai-market-frontend` for calls to removed routes; removals are a separate PR in the same round. `aim-data`: same round, remove `upload_samples` (`app/services/sample_upload_client.py`, flag-off today) and make its local publish tests treat sample members as metadata only.

Acceptance, generated rather than hand-listed: the builder's script walks the ASTs of deleted files and blocks at the base SHA and lists each removed top-level module, class, function, route path and `Settings` field, plus the named columns, `buyer_node_id`, `AIMConnectionMode.RELAY`, the `AIMTraceEventType.RELAY_*` members and the four lowercase relay event keys. Generic identifiers and literals that also have legitimate survivors (`node_id`, `"active"`) are not in the list. Each listed name must have no reference in `app` or `scripts` at the candidate SHA (word-boundary `git grep`), except an allowlist the script prints with old and new locations: `listing_license_snapshot_gate` (moved to `public.py`) and `manifest_hash` on `listing_versions` and the publishing contract. The report includes the script, its output at both SHAs, and the allowlist; nothing is added to the repo for this.
