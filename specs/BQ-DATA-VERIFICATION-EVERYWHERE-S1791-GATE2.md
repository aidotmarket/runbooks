## 3. Exact transport and control contracts

### 3.1 Two canonical encodings, kept separate

The existing fact canonicalizer is Python sorted compact JSON, UTF-8, `ensure_ascii=False`, `allow_nan=False`; it is explicitly not JCS (B:app/services/data_verification_signing.py:21-47). Gateway audit canonicalization additionally escapes `&`, `<`, `>`, U+2028/U+2029 and permits only signed int64 plain-decimal numbers (R:specs/BQ-AIM-DATA-GATEWAY-S1741-GATE2.md:408; B:app/services/aim_gateway.py:48-94). Do not use Go's normal JSON encoding to hash the legacy fingerprint.

Implement `python-json-sort-compact-v1`: recursively sort keys by Unicode code point, compact separators, Python JSON string escaping (no HTML escaping), no UTF-8 normalization of fact labels, no NaN/Infinity, and Python's numeric spelling including `-1000.0` in policy boundaries and half-even float behavior. Canonical local scalar bytes for HLL must also match §6. Canonical bytes are rechecked at input, rejecting duplicate keys, trailing bytes and alternate number spellings. NFC applies only to typed source identity preimages, not cell values or exact source column names. Gateway transport envelopes and audit entries continue using the existing gateway encoding.

To avoid the integer-only audit format rewriting embedded canonical bytes, carry spec/report/snapshot documents as **unpadded canonical base64url strings** in the gateway envelope. Decode once into a bounded byte buffer and run the original strict schema/canonical checks. Encapsulation adds no fact field and does not permit arbitrary payloads. This also prevents escaping differences from changing `spec_hash` or receipt signatures.

Shared scalar bounds: `UUID` = canonical lowercase hyphenated UUID (36 chars); `ID` = 1–128 ASCII `[A-Za-z0-9_.-]`; `H` = 64 lowercase hex; `FID` = H; nonnegative integers ≤ 2^63−1; UTC timestamps = RFC3339 UTC serialized identically to Python model JSON, with microseconds at most (no local offsets); booleans strict. No unknown keys, null optional discriminants, duplicate member identities or empty member sets. The current schemas supply ID/strict model and policy bounds (B:app/schemas/data_verification.py:109-122,269-338).

## 4. Consent, durable ledger and source snapshot

### 4.1 Signed snapshot

Build from the **active published version's retained members**, never the draft's live file list or a directory rescan. Existing gateway publication writes file IDs into `listing_version_members.relative_path` and hashes a simpler ordered manifest (B:app/services/aim_gateway_listing.py:85-109). Its `listing_versions.manifest_hash` is not the SHA of the signed verification snapshot below. Persist both: `listing_manifest_hash` internally for parity and `snapshot_hash` for verification; the signed spec's `manifest_hash` means the latter under S1791 §6.1. Do not overwrite the listing/delivery hash.

Snapshot payload exactly `{snapshot_version:"verification-source-snapshot-v1",source_kind:"gateway_listing",gateway_id:UUID,listing_id:UUID,listing_version_id:UUID,source_handle_id:UUID,members:[{file_id:FID,sha256:H,size_bytes:int≥0}]}`. Gateway id is root id; member identity is file id. Members are sorted ascending NFC identity (ASCII hex here), duplicate IDs forbidden. Every member of the pinned gateway version is included once. No paths/display names/samples or rule maps.

`manifest_hash = SHA256(python_canonical(snapshot_payload))`. Snapshot signature: compact JWS, header `{alg:"EdDSA",typ:"aim-scan-snapshot+jwt",kid:ID}`, claims `{aud:gateway_id,runner_id:UUID,manifest_hash:H,payload_b64:string}`; sign with same scan-spec key. Hash covers payload only (not signature, runner wrapper or changing issue time), so retry/rotation does not alter member-set identity. Store exact payload and JWS immutable, indexed by runner/hash and listing/version. ≤100,000 members and **≤16 MiB for the full returned JWS**; check payload AND encoded response sizes before a probe/quote. 100,000 is an upper bound, not a promise that such a snapshot fits encoding overhead (R:specs/BQ-DATA-VERIFICATION-EVERYWHERE-S1791-GATE1.md:122-133).

Fetch `GET /api/v1/verification-runners/{runner_id}/snapshot/{manifest_hash}` over existing pinned HTTPS/proxy client to `api.ai.market`. Authentication header: compact Ed25519 JWS, typ `aim-verification-snapshot-request+jwt`, kid receipt-key ID, claims exactly `{runner_id,gateway_id,method:"GET",path:<exact API path>,nonce:<43-char random>,iat:<epoch seconds>}`; ≤4 KiB. Backend verifies runner/gateway ownership, key, ≤5-minute timestamp skew and single-use request nonce in a unique DB insert retained 30 days, and serves only snapshots belonging to queued/accepted work for that runner. Stream capped response; refuse redirects, host changes, hash/signature mismatch and decoding excess. Reuse the channel's pinned client; no localhost arbitrary URL, presigned data URL or new destination. Cloud authentication adapters later supply their own outbound request wrapper without changing snapshot bytes/fact computation.

### 4.2 Consent admission

Both variants carry signed `owner_authorization_id`, `accepted_at_utc`, `listing_version_id`, fresh `nonce`, issue/expiry and addressed runner. Backend derives owner identity and consent time from the authenticated seller session, never trusts a caller's seller ID/time. Probe confirmation and paid confirmation have distinct authorization IDs/nonces. Same paid retry returns the original spec; no new authorization/nonce silently bypasses the local quota.

Require `accepted_at ≤ issued_at < expires_at`, issued lifetime ≤24 h, accepted age ≤24 h, now within issue/expiry with **5-minute skew**. Precisely: refuse if `issued_at > now+300s`, `issued_at < now−24h−300s`, `accepted_at < now−24h−300s`, or `expires_at < now−300s`. Skew does not permit >24h signed lifetime. Snapshot/listing version must equal the signed local offer version and server's active version at issuance; an old active version superseded before acceptance refuses new work. Gateway order is (a) signature, audience, key, scanner/version, signed-envelope schema/caps, snapshot binding and current offer ceiling checks using metadata only, opening no source file; (b) durable consent admission, ledger and accepted audit commit/sync (§4.3); (c) only then source schema inspection and E7, followed by pre-read and facts. An admitted request that ends in E7 refusal consumes its nonce/authorization and counts toward the daily ten; record its terminal refusal without rolling back admission. Gateway cannot independently prove a browser click; this is signed, logged, rate-limited and seller-auditable consent, as E6 expressly states (R:specs/BQ-DATA-VERIFICATION-EVERYWHERE-S1791-GATE1.md:69).

## 6. Scanner algorithms and bounds

### 6.1 Fact computation, exact S1590 v1

The approved oracle connector uses Arrow CSV/TSV/JSONL/Parquet decoding, preserves declared column order/types and reports exact row counts (L:app/services/data_verification/connectors/eolymp_v1.py:52-66,107-139,291-305,365-399). D9 instead infers from up to 10,000 values and uses a different HLL/5% rounding; do not reuse those algorithms as S1590 (G:internal/profile/profile.go:45-128).

- `row_count_algorithm_version="exact-v1"`, `row_count_method="exact"`: count every parsed data record, excluding CSV/TSV header; for Parquet, verify decoded definition levels/row groups against footer counts. Generic allowed `catalog_estimate` and `deterministic_sample_estimate(n)` remain schema vocabulary, but neither is emitted by this scanner. No sampling.
- Column names remain exact source schema order. Approved types: `string,integer,float,decimal,boolean,date,datetime,binary,unknown`. Map Arrow-equivalent logical types; null type = unknown. Reject nested/list/map/struct/repeated types, malformed UTF-8, empty/over-256-character names, unsupported types. Do not silently flatten, coerce nested JSON to strings or rename fields. Preserve Python Arrow type inference, null-token and timestamp behavior in text readers through oracle vectors; §7 requires materializing these cases, not assuming the D9 parser is equivalent.
- Null rate: let N=rows, c=nulls. For N≥10 compute q,r=divmod(c*1,000,000,N), increment q for r*2>N or tie and q odd; serialize `q//1,000,000`.`q%1,000,000` padded six decimals **as string**. Suppress when N<10, any nonzero count in `{c,N-c}`<10, or **any integer preimage** of the rounded rate intersects `[1,9]` or `[N−9,N−1]`. Find preimage endpoints by binary search on that exact half-even integer formatter. Empty objects suppress aggregate families, avoiding division by zero (L:app/services/data_verification/connectors/eolymp_v1.py:194-242,305-322).
- Distinct `hll-sha256-v1`: per column index i use `hexDecode(spec.seed)||u32be(i)` as seed. Hash `seed||NUL||canonical_local_value(nonnull)` with SHA-256; take first eight bytes big-endian x. 128 registers, index=x&127, remainder=x>>7, rank=58 if remainder=0 else 58−bit_length(remainder); retain max. Sum 2^(−register) in register order, estimate `0.7213/(1+1.079/128)*128*128/sum`; **whenever any register is zero** replace by `128*ln(128/zero_count)` (not the D9 2.5m condition). Round to nearest integer ties-to-even. Output `{algorithm:"hll-sha256-v1",estimate:int,relative_error_ppm:91924}` (L:app/services/data_verification/connectors/eolymp_v1.py:149-173,324-341).
- Distinct suppression: maintain at most ten **exact canonical distinct scalar bytes**, stop tracking exact cardinality once ten reached. N<10 or exact nonzero cardinality<10 suppresses. Also suppress if interval `[ceil(estimate*(1,000,000−91924)/1,000,000),floor(estimate*(1,000,000+91924)/1,000,000)]` intersects `[1,9]`; estimate 0 is not ambiguous. This bounded threshold test is equivalent to the legacy full exact set for the emitted suppression decision (L:app/services/data_verification/connectors/eolymp_v1.py:245-256,303-341).
- Length histograms: string/binary only, bytes length of UTF-8 string or raw binary, boundaries `[0,1,4,8,16,32,64,128,256]`; place in first bucket with length ≤ bound, final overflow bucket, ten counts. Non-applicable types emit null. Numeric buckets: integer/float/decimal converted to Python-equivalent float64; boundaries `[-1000,-100,-10,0,10,100,1000]`, first bucket with value **<** boundary; equality goes right, final overflow bucket, eight counts. Other types null. Suppress entire applicable vector if N<10 or any bucket has `0<count<10`; zero buckets alone do not suppress. No min/max/top values (L:app/services/data_verification/connectors/eolymp_v1.py:176-195,343-363).
- Canonical local HLL scalar bytes: binary=`b"bytes:"+raw`; date/datetime/time=`UTF8("time:"+Python.isoformat(value))`; decimal=`UTF8("decimal:"+format(value,"f"))`; other scalars use Python canonical JSON. Preserve decimal scale, float32→Python float representation, signed zero and date/time precision/timezone; no local-value NFC/NFKC. Non-finite scalars refuse, not alternate distinct representations (L:app/services/data_verification/connectors/eolymp_v1.py:149-156).
- Fingerprint exactly `{coverage,objects,depth_class,row_count_algorithm_version,distinct_algorithm_version,histogram_version,numeric_bucket_version,canonicalization_version}`; SHA-256 over Python canonical bytes. Sort objects/skips ascending object_id, keep column order aligned. No provenance/time/keys/D6 in fingerprint (L:app/services/data_verification/scanner.py:341-351; B:app/schemas/data_verification.py:716-727).

The issuer computes deterministic_seed as SHA256 of Python-canonical `{epoch_id:<verification_id string>,listing_id:<listing UUID string>,nonce:<spec nonce>,source_handle_id:<source UUID string>}`; Go consumes the signed seed without recomputing it or adding host-dependent randomness (B:app/services/data_verification_service.py:1005-1016). Under identical policy/seed/binding facts are byte-equal; new nonce/spec may change HLL estimates. Cross-runner comparisons explicitly fix seed and normalize identities.

### 6.2 Streaming parser policy

Two full byte passes over every pinned member: pre-read verification then fact-time read with rehash. Streaming read chunks ≤64 KiB; CSV quoted record/JSONL line ≤16 MiB, scalar ≤16 MiB, schema ≤1,000 columns; single verification worker. Policy working-memory ceiling **128 MiB additional**, including decompression buffers, ten distinct scalar representatives per column and accumulated report; refuse before allocations exceed it. Store bounded scalar representatives locally only; no spill of raw values or temp dataset copies. Ten huge values across many columns can exceed the ceiling and must refuse. Deadline 30 minutes for a full operation, cancellation checked between chunks/batches. Probe must refuse if a supported complete depth cannot fit; a runtime overrun gives terminal timeout/void, never truncated success. Measure combined gateway memory with eight existing download buffers; do not claim 128 MiB whole-container memory.

CSV/TSV use explicit delimiter and Arrow-equivalent header/quoted multiline records, uniform column widths and complete UTF-8 decoding. JSON Lines accepts one flat object per line, missing fields as null, stable schema/order as the Python oracle; reject duplicate keys/nested values/non-objects. Parquet reads pages/definition levels in batches ≤1,024 rows via existing arrow-go `parquet/file`; distinguish logical decimal/date/timestamp/binary types correctly, handle dictionary and none/snappy/gzip/zstd compression; all row groups traversed, no footer-only fact shortcut. Refuse over-limit decoded pages rather than allocate first. Existing gateway reads these codecs in tests and uses `parquet/file` without pqarrow (G:internal/profile/profile.go:20-25,301-371,393-474; G:internal/profile/profile_test.go:92-120). D9 parsing helpers may be reused only when vectors prove identical semantics; retain the separate D9 accumulator.

Each gateway member is one object; do not expand ZIP payloads or recurse into embedded archives. Unsupported containers/formats have a disclosed `unsupported_type` skip following directory-root precedent, still included in pre-read content verification and coverage. Bounds known before quote yield the same fixed skip/refusal prediction in probe. A complete depth covers **all reachable supported objects**, not partial traversal of a supported object. Never turn mutation, missing pinned member or out-of-scope membership into a skip (R:specs/BQ-DATA-VERIFICATION-S1590-DIRECTORY-ROOT-AMENDMENT.md:30-34; R:specs/BQ-DATA-VERIFICATION-EVERYWHERE-S1791-GATE1.md:133).

Fact-result canonical bytes (including schema preview, as legacy connector bounds it) ≤8192*4=32,768 before report assembly; over-limit refuses. Backend still performs actual provider token counting before the single narrative request; 4 bytes/token is only scanner envelope admission, not proof of model-token compliance (L:app/services/data_verification/connectors/eolymp_v1.py:388-402; R:specs/BQ-DATA-VERIFICATION-S1590-GATE3-C4.md:16-18).

### 6.3 Gateway source binding, no TOCTOU

With independent local commitment key K, exact UTF-8 NFC typed preimages. For `gateway_listing` every preimage input is ASCII (canonical UUIDs and lowercase hex), so NFC is the identity and no normalization library is required; exact source column names are never normalized. Cloud source kinds settle their normalization source in their own Gate 2:

```text
locator = gateway_listing\0<gateway_uuid>\0<snapshot_hash_hex>
object  = object\0gateway_listing\0<gateway_uuid>\0<file_id>\0<member_sha256_hex>
artifact_locator_commitment = hex(HMAC-SHA256(K, locator))
object_id = hex(HMAC-SHA256(K, object))
content_sha256 = hex(SHA256(concat in ascending file_id order:
    u64be(len(file_id_utf8)) || file_id_utf8 || u64be(size_bytes) || raw32(member_sha256)))
```

NUL is a single zero byte; UUID/FID/hash have no NUL; size integer framing unsigned 64-bit big-endian. No trailing delimiter. Raw member hashes are recomputed, not merely trusted from snapshot. Membership changes alter content framing; commitment-key changes alter object/locator commitments but not content hash; version-only re-publication of identical members changes snapshot/locator but leaves object/content hashes unchanged. This follows the approved preimages verbatim (R:specs/BQ-DATA-VERIFICATION-EVERYWHERE-S1791-GATE1.md:127-136).

Resolve local files only by gateway ID/file ID in inventory/ledger; prove regular file, no symlink escape and current offer ceiling, listing-key offer for this version/SHA and any configured local approval. Before facts, open every member safely and stream hash/size; compare to signed snapshot, bracket with stat. During fact read, reopen under the same no-follow containment checks, hash all bytes consumed; Parquet random access also requires a final sequential hash of the same open file plus stat/block integrity, since footer/page read order is not the file's SHA order. Validate each fact-producing block against pinned block hashes before decoding; finish member verification before releasing its facts. Any size/hash/stat mismatch, missing member, ceiling escape or unpinned file → `artifact_changed`/FAILED_VOIDED; discard all partial facts. Same-size/same-mtime mutation tests are mandatory. The gateway already stores block hashes and checks offer ceilings, so use those primitives without treating mtime as content truth (G:internal/ledger/ledger.go:77-87; G:internal/gateway/gateway.go:190-209; R:specs/BQ-AIM-DATA-GATEWAY-S1741-GATE2.md:440-452).
