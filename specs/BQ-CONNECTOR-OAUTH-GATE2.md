## 3. Cross-spec contract

`app/mcp/connector_shared/` is key-free and imported by the resource, AS, and main backend. It owns `contracts.py` with the exact Gate 1 §5.3 interfaces below, `grants.py` with **both** `revoke_grant` and `revoke_all_for_user`, `profiles.py`/`profiles.yaml`, `scopes.py`, `audit.py`, `oauth_models.py`, and `oauth_store.py` with create/replace grant and single-use consent-ticket functions. `oauth_store.py` must not define either revocation hook. `app.mcp.connector` and `app.main`/`app.api`/`app.services`/`app.actions` may import shared but never `app.mcp.connector_auth`; AS may import shared but never resource; shared imports neither. Static AST and fresh-process import tests enforce this. Only `ai-market-connector-auth` has `CONNECTOR_OAUTH_SIGNING_KEYS`; `ai-market-connector` and backend refuse or fail the pre-enable variable-name check if it is present.

```python
@dataclass(frozen=True)
class VerifiedToken:
    user_id: UUID; client_id: str; grant_id: UUID; token_jti: str
    scopes: frozenset[str]; issuer: str; audience: str; expires_at: datetime

class TokenVerifier(Protocol):
    async def verify(self, token: str, *, resource: str) -> VerifiedToken | None: ...

@dataclass(frozen=True)
class Grant:
    grant_id: UUID; user_id: UUID; org_id: UUID | None; client_id: str
    scopes: frozenset[str]; profile: Profile; revoked_at: datetime | None

class GrantStore(Protocol):
    async def load_active_grant(self, grant_id: UUID) -> Grant | None: ...
```

Construct `VerifiedToken` with keyword arguments; `token_jti` is the JWT `jti` and fourth declared field. The verifier returns `None` for invalid ES256/issuer/audience/expiry/jti; the resource then checks token/grant user, client, scopes and live org membership on every request (personal grant means no active membership). No grant cache in P0. Fakes implement both protocols before the AS implementation lands; the same contract suite runs with fakes and with OAuth's real verifier/store. Canonical issuer `https://auth.ai.market`, audience/resource `https://connect.ai.market/mcp`, public JWKS `https://auth.ai.market/.well-known/jwks.json`; no `/mcp/openai` alias. Scope filtering uses all required scopes. A DCR client is always `default`; elevated Claude/OpenAI profiles require validated allowlisted CIMD identity, pinned document hash and matching redirect, with downgrade of live grants on drift.

Foundation means Chunk 0 deployed, then one shared additive revision `s_connector_foundation_001` creating `connector_switches`, `connector_audit_events` and `connector_review_queue`, shared profile/scope catalogue and interfaces/fakes/contract tests, both Railway JSON files, A23 isolation check, and the health-only `app/mcp/connector_auth/asgi.py` stub. Backend web owns migration execution; neither new service migrates on startup. The auth service is configured with both flags off only after this inert foundation. OAuth revision `s_connector_oauth_001` depends on the foundation revision, is additive, and its downgrade retains all five OAuth tables.

`connector_audit_events` is the sole connector audit table, append-only and retained pending legal sign-off. The fixed `event_type` CHECK catalogue is `tool.call`, `http.auth_failure`, `oauth.grant_created`, `oauth.grant_superseded`, `oauth.grant_revoked`, `oauth.grant_downgraded`, `oauth.refresh_reuse_detected`, `oauth.registration_created`, `action.confirm`, `action.decline`. Tool-call fields are nullable for OAuth/HTTP rows; `tool.call` requires tool/user/grant/client/args HMAC and is unique by request id. Writers use `AuditSink`; `record_required` joins a write effect's transaction. `tests/connector/test_audit_contract.py` inserts one valid row for every event type and rejects a duplicate tool call. ## 4. Protocol routes and trust rules

AS routes are `GET /.well-known/oauth-authorization-server` (RFC 8414), `GET /.well-known/jwks.json`, `GET /oauth/authorize`, `GET /oauth/authorize/complete`, `POST /oauth/token`, `POST /oauth/revoke`, and `POST /oauth/register` only when DCR is enabled. The RFC 8414 metadata fixture (full equality, with the listed order of arrays) is:

```json
{
  "issuer": "https://auth.ai.market",
  "authorization_endpoint": "https://auth.ai.market/oauth/authorize",
  "token_endpoint": "https://auth.ai.market/oauth/token",
  "revocation_endpoint": "https://auth.ai.market/oauth/revoke",
  "jwks_uri": "https://auth.ai.market/.well-known/jwks.json",
  "scopes_supported": ["account.read", "market.read", "buyer.write", "orders.read", "orders.write", "seller.read", "seller.write", "seller.publish", "seller.fulfil"],
  "response_types_supported": ["code"],
  "grant_types_supported": ["authorization_code", "refresh_token"],
  "code_challenge_methods_supported": ["S256"],
  "token_endpoint_auth_methods_supported": ["none", "client_secret_basic", "client_secret_post"],
  "authorization_response_iss_parameter_supported": true,
  "service_documentation": "https://ai.market/docs/connector-oauth"
}
```

Add `"registration_endpoint": "https://auth.ai.market/oauth/register"` if and only if `CONNECTOR_DCR_ENABLED=true`; add `"client_id_metadata_document_supported": true` if and only if `CONNECTOR_CIMD_ENABLED=true`. Both fields are absent when their flags are off. `client_secret_*` methods apply only to DCR clients; CIMD clients use `none` in P0. `test_metadata.py::test_as_metadata_shape` compares the complete document to this fixture for all flag combinations, rejecting missing or extra members, added authentication methods, and incorrect conditional fields. `POST /oauth/register` is 404 when DCR is off; there is no OIDC discovery route. Core serves RFC 9728 PRM at `/.well-known/oauth-protected-resource` and `/mcp` variant with exact `resource=https://connect.ai.market/mcp` and `authorization_servers=[https://auth.ai.market]`, plus a bearer challenge whose `resource_metadata` parameter points to that PRM on 401. `/mcp/openai` does not exist. Metadata/authorization/refresh routes 404 with master flag off, but JWKS and health stay served.

`GET /oauth/authorize` validates client identity and redirect first; invalid client/redirect gets a static 400 without redirect. Require `response_type=code`, PKCE S256 challenge 43–128 chars, scopes in catalogue and client/profile ceiling, state ≤512 chars. `resource` absent defaults to the sole canonical resource; present must match byte-for-byte here and at `/oauth/token`, including rejection of trailing slash/alias. Scope absent defaults to `account.read market.read` per Gate 1. After validation, create 30-minute transaction, 256-bit request id stored hashed, hashed browser-binding cookie (`HttpOnly`, `Secure`, `SameSite=Lax`, host-only `auth.ai.market`, path `/oauth`, 30 minutes) and 303 to `https://ai.market/oauth/connect?request=<id>`. A request is not recoverable after 30 minutes: show reconnect/restart, never silently approve. If email verification occurs on another device, that device may verify the account, but it lacks the original binding cookie; show reconnect there and require a new `/authorize` flow in the original client. This is Max's cross-device decision. Same-device verification may resume before expiry.

Consent uses backend `GET /api/v1/connector-oauth/requests/{request}` and `POST .../{request}/decision` with website bearer session, exact frontend Origin, CSRF nonce, active user/email verification, SSO policy and 2FA assurance. Render client display name **and host**, Verified only for pinned allowlisted CIMD or pre-registered identity, org or Personal account, scope descriptions from shared catalogue, expiry, Approve/Deny. On approve `oauth_store.py` supersedes previous active grant in one transaction, stores one 60-second hashed ticket, and returns only an auth-host `continue_url`. Browser top-level navigation to `/oauth/authorize/complete` must match the original cookie, consume ticket once, issue 60-second one-use code bound to grant/client/redirect/challenge/resource, and redirect to the validated URI with `code`, `state`, `iss=https://auth.ai.market` (RFC 9207). Denial and post-validation errors use error/state/iss. Cookie mismatch, expired transaction and replay fail without code. Codes, tokens, tickets and OAuth query values are redacted from logs; sensitive responses are `Cache-Control: no-store`.

CIMD: `client_id` must be an HTTPS URL on port 443 without userinfo/fragment; fetch 5 KB JSON with 5-second timeout, no redirects, public-IP DNS checked before and after connect, document `client_id` equal byte-for-byte, valid redirect list, cache between 5 minutes and 24 hours, last good document at most 24 hours. Parse plural `token_endpoint_auth_methods_supported`; CIMD in P0 accepts `none`, even if legacy singular preference is `private_key_jwt` (ChatGPT fixture). If plural absent, singular must be `none`. All allowlisted Claude/ChatGPT entries in shared `profiles.yaml` require operator-pinned canonical JSON SHA-256 and matching redirect. `python -m app.mcp.connector_auth.ops pin-cimd <client_id>` records reviewed pin; exact live URLs/documents/hashes are **UNVERIFIED** until fetched and reviewed. Refresh revalidates; hourly AS leader refetches pinned clients so every one is checked within 24 hours. Mismatch, invalid document or no good fetch for 24 hours downgrades all active grants of that client to `default` and `client_verified=false` in one transaction, one `oauth.grant_downgraded` row per grant. Re-pin requires operator review. DCR (RFC 7591) permits at most **10 registrations per IP per hour and 1000 registrations globally per day**; the 11th per-IP and 1001st global attempts are rejected without consuming quota. Names are sanitized to ≤80 printable characters; IDs are 256-bit `dcr_` values; only confidential clients get an Argon2id secret; PKCE is required even for them. DCR is always `default`/Unverified, even with a vendor redirect.

The complete initial non-loopback redirect allowlist, matched as exact strings, is:

- `https://claude.ai/api/mcp/auth_callback`
- `https://claude.com/api/mcp/auth_callback`
- `https://chatgpt.com/connector_platform_oauth_redirect`
- `https://vertexaisearch.cloud.google.com/oauth-redirect`

Loopback permits `http://localhost:<port>/<path>`, `http://127.0.0.1:<port>/<path>` and `http://[::1]:<port>/<path>` on any port, with only the port varying during registered-URI matching. It is available only to `application_type=native` DCR clients or CIMD documents; web DCR clients cannot use it. All other components must match the registered URI exactly. No wildcard or unverified alias is accepted, and no custom scheme is accepted unless a Cursor scheme is vendor-documented and added by reviewed PR. Cursor and Copilot Studio callbacks remain absent until each exact URI has a cited vendor source in `redirect_allowlist.py`. `test_registration.py` uses table-driven, clock-controlled tests for the two numeric limits and loopback/application-type boundary. `test_authorize.py` and `test_trust.py` enumerate every allowed non-loopback URI above and reject aliases, wildcard strings, and unverified Cursor/Copilot callbacks; Gate 4 records the reviewed limits and redirect set.
