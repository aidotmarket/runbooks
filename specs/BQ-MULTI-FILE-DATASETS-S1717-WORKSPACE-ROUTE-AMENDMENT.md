## 1. What the workspace route already has (no change)

- **One listing = N objects.** A workspace listing version is published from the seller's frozen source selection: `SourceContent.objects` (`app/schemas/seller_listing_source.py:14-19`, `min_length=1, max_length=MAX_SELECTION_FILES`, `MAX_SELECTION_FILES = 50_000`, `app/schemas/seller_source_limits.py:2`, whose docstring records "customer acceptance includes 22,000 files"). Publication writes `ListingVersion(object_count=len(objects), total_size_bytes=sum(size), manifest_hash=approval.source_snapshot['input_hash'])` (`app/services/seller_listing_publication.py:132-135`), `prefix='workspace/<approval_id>/'` (`:133`), `authority_kind='workspace_connection'` (`:138`). The parent's D0 requirement — one frozen manifest per version, identified by `manifest_hash` — is therefore **already met** on this route by a different, route-native manifest: `input_hash = sha256(SourceContent.model_dump_json())` (`app/services/seller_listing_approval.py:44`), frozen into `SellerListingApproval.source_snapshot` as the encrypted envelope (`:49-63`). This amendment does **not** replace it with the parent's `python-json-sort-compact-v1` manifest: the workspace manifest is keyed by provider `etag` and `size` per object (`SourceObject`, `seller_listing_source.py:7-12`), not by SHA-256 of bytes, because ai.market never reads the seller's bytes before purchase on this route.
- **Delivery is the whole set.** `seller_workspace_delivery.py` delivers every object of the approved source (`:151` refuses when `version.object_count != len(source.objects)` or the total size differs; grants are `workspace_direct` per object, `:281`, `:317`), resolved through `SellerApprovedSourceIndex` (`app/services/seller_approved_source_index.py`, chunks of `CHUNK_FILES = 64` objects, `:16`, `:81-104`). The buyer already receives the original files unchanged. Nothing here changes.
- **Provider parity.** Publication accepts `provider in {'aws','r2'}` (`seller_listing_publication.py:102`); R2 objects are validated with `validate_object` and must have `version_id is None` (`:113-116`). AWS profiling (W3) is not a precondition for publication on either provider.

## 2. The gap

`ListingApprovalRequest.sample_decision: Literal['none']` (`app/schemas/seller_listing_approval.py:14`, receipt `:36`) and `CheckConstraint("sample_decision = 'none'", name='ck_listing_approval_sample')` (`app/models/seller_listing_approval.py:12`). The schema comment at `:11-12` says it: "A public sample requires its own bounded, reviewed artifact contract." A workspace seller today — AWS or R2 — can offer **no free sample at all**: `approved_rows` is an AIM Data disclosure-snapshot concept (`app/schemas/disclosure_snapshot.py:96`, `:105`, `:136`, `:178`) and never reached the workspace approval; `seller_listing_public_presentation.py:58` renders the public listing only when `sample_decision == 'none'`. The parent's D4 defines the seller-chosen sample-file surface for the local route only ("owned by chunk C: at publish, AIM Data uploads the sample members …"). A seller of 21,000 files on R2 would therefore ship a listing with no way for a buyer to inspect one file before paying — the same customer problem as the trigger, on the route the trigger customer is actually on.

## 3. Decision

**W-D1. `sample_decision = 'member_files'` on the workspace approval.** `ListingApprovalRequest.sample_decision` widens to `Literal['none','member_files']` (`seller_listing_approval.py:14`; receipt `:36`); the CHECK at `seller_listing_approval.py:12` widens with a migration; `SellerListingApproval` gains `sample_object_indices: JSON NOT NULL DEFAULT '[]'` — the **indices into the frozen `SourceContent.objects` list** the seller chose, validated at approval against the same `source.content` whose `input_hash` the approval freezes (`seller_listing_approval.py:37-45`): every index in range, strictly ascending, no duplicates, `len ≤ SAMPLE_MAX_FILES`, `sum(objects[i].size) ≤ SAMPLE_MAX_TOTAL_BYTES`, and **each `objects[i].size ≤ SAMPLE_MAX_FILE_BYTES`** (Max's mandatory per-file limit, Event Ledger `2ab397f2`; all three are Gate 2 values shared with the parent's D4 — one policy, two routes). `member_files` pairs with a non-empty index list; `none` pairs with an empty one (CHECK). The request carries the indices; `request_hash` (`:27`) therefore binds them, and the existing idempotent-conflict rule (`:29-31`) applies unchanged. The existing `public_disclosure_confirmed` statement already says "the listing fields and my sample choice become public on ai.market" (`seller_listing_confirmations.py:6`); for `member_files` the confirmation screen additionally lists the chosen file names and sizes next to it, and `CONFIRMATION_STATEMENTS` gains one statement (`sample_files_confirmed`: the chosen files may be downloaded free by anyone and are part of the purchased set), required only when `sample_decision = member_files` — the workspace counterpart of D4's "seller-consented public artifact".

**W-D2. Sample bytes are copied into ai.market's listing-asset store at publication; the seller's bucket is never exposed publicly.** At `seller_listing_publication.py` publish (after the provider checks at `:102-116`, before the listing is flushed), for each `sample_object_indices` entry the backend reads the object from the seller's connection using the **existing delivery read path** for that provider (the same code path `seller_workspace_delivery.py` uses to serve a purchased object — no new credential scope; the read is a `listing_publication` audit purpose, `seller_workspace_audit`, one row per sample object), verifies `size` and `etag` against the frozen manifest entry (mismatch → `PublicationConflict`, nothing published — the seller's selection changed under him, same class as the existing `:151` check), streams it to the listing-asset object store under the parent's D4 disclosure-asset layout **bound to the version's `manifest_hash`** (here the workspace `input_hash`), computing SHA-256 while streaming, and stores `{index, key_basename, size, sha256}` per sample on the publication row (`SellerListingPublication.sample_assets`, JSON) — `key_basename` is the object key's final path segment only, so no private prefix or bucket name becomes public. Publication is one transaction: if any sample copy fails the listing is not created and the copied assets are deleted. Bounds at publish: `SAMPLE_MAX_FILES`, `SAMPLE_MAX_TOTAL_BYTES`, `SAMPLE_MAX_FILE_BYTES` are re-checked against the bytes actually read (a stream longer than the declared size is refused). **Why copy rather than proxy on demand:** proxying would make every anonymous sample download a credentialed read of the seller's bucket (cost and a new abuse surface on customer infrastructure) and would let the sample drift from the manifest; a copy at publish gives immutable, hash-known bytes served by the same bounded surface D4 already defines.

**W-D3. Serving reuses the parent's D4 surface verbatim.** The public listing serves sample files addressed only by `(version_id, index)` from the approved list, hash-verified before response, `Content-Type: application/octet-stream` + `Content-Disposition: attachment`, opaque non-guessable addressing with `X-Content-Type-Options: nosniff` and a per-listing daily byte budget (CC's Gate 1 nits on the parent, carried into Gate 2), rate-limited per listing and per client, not enumerable. The public presentation (`seller_listing_public_presentation.py:58`, `:71`) renders `member_files` with the sample list `{index, key_basename, size}` and the statement that sample files are part of the purchased set and free to download. **Lifecycle** as D4: sample URLs serve only while the version is `active` and the listing is published; they stop on unpublish/withdrawal/takedown and on connection disconnect (`seller_workspace.py:487` `disconnect_connection`; sample serving applies the same connection-status condition publication and delivery already apply — `connection.status == 'verified'`, `seller_listing_publication.py:102` — so a disconnected connection serves no sample), and the assets are deleted with the version. (`seller_workspace_listing_guard.py` is the legacy-mutation guard and is not involved.) The rows-sample route keeps answering `member_files` with 409 `no_approved_sample_rows` (parent D4); Hugging Face is out of scope for workspace listings (no HF publish exists on this route today).

**W-D4. No roles, no manifest change, no delivery change on this route.** Every workspace object remains a delivered object (there is no `data`/`docs`/`other` role on this route and this amendment adds none — the seller's selection *is* the product); `SourceObject` stays `key/version_id/etag/size` (`seller_listing_source.py:7-12`); `manifest_hash` stays `input_hash`; `SellerApprovedSourceIndex` and `seller_workspace_delivery.py` are untouched; the D5 transfer protocol, D6 verification amendment and D8 registration do not apply here (the seller's files are never traversed by ai.market). The parent's D7 (verified label optional) already holds on this route: workspace publication has no verification precondition.

**W-D5. R2 profiling is out of scope** (W3 is AWS-only Lambda, `build:bq-seller-workspace-w3-profiling-s1650`, blocked on its server-authority redesign). A workspace seller lists and samples without profiling on either provider; nothing in this amendment depends on W3.

## 4. Non-goals

No change to the S3 device route or S1681 G3.2; no change to AIM Data's D4 mechanics (this amendment consumes the same surface and policy values); no change to pricing, commission, payout, the delivery grant model, `MAX_SELECTION_FILES`, the connection/credential model, or the Trust Channel. No on-demand proxying of seller-bucket bytes to anonymous clients. No sample for `version_mode = 'versions'` selections beyond what the frozen `SourceObject.version_id` already pins (R2 refuses `version_id`, `seller_listing_publication.py:115-116`). No archive/zip of sample files.

## 5. Customer-visible behaviour

1. In the workspace listing review (W4/W5), the seller ticks the files he wants to give away as the free sample (bounded: count, total bytes, per-file bytes — the UI shows the limits and refuses over-limit files by name before approval).
2. The published listing shows "Free sample: N files" with the file names and sizes and a download link per file; the buyer needs no account.
3. Purchase delivers the whole selection exactly as today.
4. Unpublishing, withdrawing or disconnecting the connection makes the sample links stop; nothing about the seller's bucket, prefix or account is ever shown.

## 7. Acceptance criteria

- **AC-W1.** An R2 connection with 21,000 objects approves with three chosen sample files, publishes one listing with `object_count = 21000`, `sample_decision = member_files`, three sample assets whose SHA-256 match the bytes read from the bucket, three `listing_publication` audit rows, and the seller's bucket name/prefix/key prefix appearing nowhere in any public response (asserted by grep over the listing page, the sample list and the sample response headers).
- **AC-W2.** An approval naming an out-of-range, duplicate, over-`SAMPLE_MAX_FILE_BYTES` or over-total index is refused at approval with the offending index named; a publish whose sample object's `etag`/`size` no longer match the frozen manifest is refused with `PublicationConflict` and creates no listing, no version and no asset.
- **AC-W3.** Sample download without authentication returns the exact bytes with `application/octet-stream`, `attachment`, `nosniff`; enumeration of `(version_id, index)` outside the approved list returns 404 indistinguishable from a non-existent listing; the per-listing daily byte budget and per-client rate limit are enforced; after unpublish or `disconnect_connection` the same URL returns 404 and the assets are gone.
- **AC-W4.** `sample_decision = none` approvals and every existing published workspace listing are byte-identical in behaviour before and after the migration (fixture: a copied production-shaped approval + publication row).
- **AC-W5.** An AWS connection passes AC-W1–W3 identically (provider parity), with no profiling job existing for the connection.

## 8. Risks

- Sample bytes are seller-consented public artifacts copied off the seller's infrastructure: the copy is bounded (three policy values), verified against the frozen manifest, and hashed; the only new read of the seller's bucket happens once, at publish, under the existing delivery credential scope and with an audit row. Mitigation of a wrong tick: the seller sees the file names and sizes at confirmation and signs a dedicated statement.
- Policy values are shared with the parent's D4: a change to one route's limits changes the other's. This is intended (one product rule) and stated so Gate 2 pins them once.
