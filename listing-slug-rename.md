# Listing slug rename

## Purpose

A listing's slug is public: it appears in the listing URL, in JSON-LD, in the
sitemap and in the names of the metadata cards we mirror to Hugging Face and
Kaggle. When a slug names the seller (for example a company name), it breaks
the anonymity rule (CORE P5/S1; `ai-market-backend` runbook
`runbooks/public-seller-anonymity.md`). This page renames such a slug to a
neutral one without losing the listing's links. It is a production-data
change, so the exact procedure for a given listing is Council-approved before
it runs.

First use: listing `5ab53e16-ca71-4d5b-8d55-794420d3b800`,
`eolymp-problem-dataset-5ab53e16` → `competitive-programming-problems-5ab53e16`.
The title is already neutral ("Competitive Programming Problems").

## What depends on the slug

| Surface | How it uses the slug | What the rename must do |
| --- | --- | --- |
| `listings.slug` | Public URL `https://ai.market/listings/{slug}`, API `/public/listings/{slug}` | Set the new value (unique). |
| `listings.jsonld` | `url` is built from the slug; `sameAs` lists the card mirrors | Regenerated by the card publishers (`huggingface_service.py`, `kaggle_service.py` call `generate_listing_jsonld`) once the new cards publish. |
| `listings.source_delivery` | `huggingface_url`, `kaggle_url` of the existing mirrors (named from the old slug) | Remove both keys so the publishers create new mirrors named from the new slug instead of versioning the old ones. |
| Hugging Face mirror | Repo `ai-market/{slug}-sample` | New repo created by the job. Set the old repo to private. Never delete it. |
| Kaggle mirror | Dataset `maxrobbinsaimarket/{slug, max 50 chars}` | New dataset created by the job. Set the old dataset to private. Never delete it. |
| Frontend | Old URL must keep working | Merge a permanent redirect old → new (`next.config.ts` `redirects()`), AFTER the database change. |
| Search | Qdrant payload has no slug; every search query reads `l.slug` from Postgres (`listing_search_service.py`) | Nothing to do; verify only. |
| Sitemap / llms | Built from the database | Nothing to do; verify only. |
| Share links | `listing_share_links` keyed by listing id | Nothing to do (verify the count; 0 for the first use). |

## Procedure

Database access: the prod DSN script `scripts/test-db-dsn.sh` in the ai-market
workspace, exactly as in `dataset-card-publishing.md` E-02. Card-channel tokens:
`HUGGINGFACE_TOKEN`, `KAGGLE_USERNAME` and `KAGGLE_API_TOKEN` from Infisical
`ai-market-backend` prod (never printed or pasted into chat).

1. **Pre-check (read-only).** Confirm the id, the old slug and the
   `source_delivery` URLs. Confirm there are no orders and no share links for
   the listing. Confirm the new slug is unused
   (`select count(*) from listings where slug = '<new>'` returns 0). Record all
   of it in the release evidence.
2. **Rename in one transaction**, guarded on the old slug:

   ```sql
   begin;
   set local lock_timeout = '5s';
   update listings
      set slug = '<new>',
          source_delivery = coalesce(source_delivery, '{}'::jsonb) - 'huggingface_url' - 'kaggle_url',
          updated_at = now()
    where id = '<listing-id>' and slug = '<old>';
   -- expect UPDATE 1; anything else: rollback
   commit;
   ```

3. **Republish the cards.** Insert one `huggingface` and one `kaggle`
   `updated` job for the listing, using `dataset-card-publishing.md` E-02.
   Wait for both to reach `succeeded`. Then read back `source_delivery` (new
   URLs named from the new slug) and `jsonld` (the `url` uses the new slug;
   `sameAs` lists only the new mirrors).
4. **Merge the frontend redirect** (branch with the `redirects()` entry old →
   new, `permanent: true`). Merge only after step 2, so that the old URL never
   redirects to a 404. Frontend deploy per the frontend deploy runbook.
5. **Make the old mirrors private.** Hugging Face:
   `HfApi().update_repo_settings(repo_id="ai-market/<old>-sample", repo_type="dataset", private=True)`
   (older library versions: `update_repo_visibility`). Kaggle: set the old
   dataset private through the Kaggle dataset settings API
   (`kaggle` client `dataset_update_settings` with `isPrivate: true`) or, if
   the account's API rejects it, through the dataset's Settings page. Never
   delete either one.
6. **Verify from outside:**
   - `https://ai.market/listings/<new>` returns 200.
   - `https://ai.market/listings/<old>` returns 308 to the new URL.
   - `https://api.ai.market/api/v1/public/listings/<new>` returns 200 and has no seller identity.
   - The page's JSON-LD `url` uses the new slug.
   - The new HF and Kaggle cards return 200 and link back to the new URL.
   - The old HF and Kaggle URLs are no longer public (401 or 404 when logged out).
   - A marketplace search for the title returns the new slug.

## Rollback

Before step 5, the rollback is to reverse step 2 with the same guarded
`update` (swap old and new) and restore the two `source_delivery` URLs from the
step-1 record. The new card jobs republish to the old mirrors on the next
`updated` event. After step 5, also set the old mirrors public again. Nothing
is deleted at any step, so every state is recoverable.

## When it breaks

- `UPDATE 0`: the slug changed since the pre-check, or the id is wrong. Stop and re-run step 1.
- Unique violation on `slug`: the new slug already exists. Stop, and pick a different neutral slug with Council.
- A card job ends `dead`: follow `dataset-card-publishing.md` When it breaks. The database rename stands (links work through the redirect). Re-enqueue after the fix.
